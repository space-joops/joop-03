# ADR-0001 · 국제화(i18n): proxy + [lang] + 서버 dictionaries

- 상태: 제안됨(Proposed)
- 관련: FR-0.1 (10개국어, 설정 변경, 영어 폴백)

## 배경 / 문제

10개 주요 언어를 지원하고 설정에서 바꿀 수 있어야 하며, 지원하지 않는 로케일은 **영어로 폴백**해야 한다. 이 프로젝트의 커스텀 Next.js 16.2.12는 **App Router에 내장 i18n 라우팅이 없다**(구 Pages Router의 `next.config.js` `i18n` 키는 App Router에서 동작 안 함).

## 결정

공식 문서(`node_modules/next/dist/docs/01-app/02-guides/internationalization.md`)가 권장하는 패턴을 채택한다.

1. **로케일 라우팅**: `app/[lang]/` 동적 세그먼트 아래에 모든 페이지/레이아웃을 둔다. `params`는 Promise이므로 `const { lang } = await params`.
2. **로케일 감지·리다이렉트**: 루트의 **`proxy.ts`** (⚠️ 구 `middleware.ts`가 v16에서 **`proxy`로 개명**, **Node 런타임 전용·edge 미지원**)에서 `Accept-Language`로 로케일을 정하고, 경로에 로케일이 없으면 붙여서 리다이렉트. **영어 폴백은 여기 `getLocale()`의 defaultLocale로 처리**.
3. **사전(dictionaries)**: `import 'server-only'` 로 서버에서만 JSON을 동적 import. `hasLocale()` 타입 가드로 미지원 로케일은 폴백/404. 서버 컴포넌트에서만 로드되므로 **10개국어여도 클라 번들 크기에 영향 없음**.
4. **정적 렌더**: `generateStaticParams`로 지원 로케일을 미리 생성(대체로 정적인 PWA에 유리).
5. **언어 변경 UI**: 설정/상단 바에서 로케일을 바꾸면 해당 `/[lang]` 경로로 이동 + 선호 로케일 저장(쿠키).

## 대안

- **next-intl / next-international 등 서드파티**: 기능은 풍부하나 의존성·러닝커브 추가. 커스텀 Next 버전과의 호환을 별도 검증해야 함.
- 결론: 초기에는 **내장 패턴(무의존성)** 으로 가고, 메시지 관리가 복잡해지면 서드파티를 재검토한다.

## 영향

- 모든 라우트가 `app/[lang]/...` 아래로 들어간다(루트 레이아웃의 `<html lang>` 동적화).
- `middleware.ts`가 아니라 **`proxy.ts`** 를 만든다. edge가 필요해지면 그 부분만 예외적으로 `middleware` 유지 검토.
- 문자열 하드코딩 금지 — 모든 UI 텍스트는 dictionary 키.
- SEO: `alternates.languages`(hreflang)를 메타데이터에 연결.

## 미해결

- 지원 10개 언어 목록 확정(및 CJK/키릴 폰트 subset 전략 → [ADR-0002](./0002-pwa-portrait.md)/폰트).
- 번역 워크플로우(수기 JSON vs 번역 관리 도구).
