# ADR-0003 · 게임 렌더링: Canvas 2D 중심

- 상태: 제안됨(Proposed)
- 관련: FR-1.2(궤도 시각화), EPIC 7(아케이드 모드)

## 배경 / 문제

첫 화면의 궤도 지구본과 아케이드 모드(우주 쓰레기·조이스틱·배경 천체)를 렌더링할 기술이 필요하다. 모바일 세로·저사양 기기에서도 부드러워야 하고, 개발 난이도가 계단식으로 오르길 원한다.

## 결정

**Canvas 2D API를 기본 렌더링 기술로 채택**한다(사용자 합의).

- 첫 화면 궤도(FR-1.2): Canvas 2D로 지구 + 경위도 그리드 + 줍스 점 + 궤도 링. `requestAnimationFrame` + devicePixelRatio 대응.
- 아케이드 모드(EPIC 7): 동일하게 Canvas 2D. 쓰레기는 2D 스프라이트, 위성은 스케일 변화로 원근감(FR-7.7).
- 필요한 특정 효과(웅장한 천체·파티클 다수)에서만 **부분적으로 WebGL 검토** — 전면 3D 엔진은 도입하지 않는다.

## 대안

- **WebGL / Three.js(3D)**: 태양·달·은하수의 경이로운 3D 표현에 유리하나, 번들·복잡도·모바일 성능 부담이 크다. 초기엔 과하다.
- **DOM/SVG + CSS**: 프로토타입엔 쉬우나 100개 개체 60fps·아케이드 실시간엔 부적합.

## 근거

- 요구 시각은 대부분 2D 투영(지구본, 상하좌우 아케이드)이라 Canvas 2D로 충분.
- 단일 기술로 궤도(M1) → 지상 미니게임(M3) → 아케이드(M5)까지 난이도를 점증시키며 재사용.
- 서버사이드 렌더링을 적극 활용(FR-7.5)하되, 실시간 인터랙션은 클라 Canvas가 담당.

## 영향

- 렌더링 유틸리티(rAF 루프, 좌표 투영, 스프라이트 로더)를 `lib/`에 공용화.
- `prefers-reduced-motion`·Canvas 미지원 폴백(정지 스냅샷) 필요.
- 성능 예산: 첫 화면 100개 60fps, 아케이드 프레임 예산 관리(오브젝트 풀링).

## 미해결

- 아케이드에서 WebGL 부분 도입 경계선(어떤 효과부터).
- 스프라이트 에셋 파이프라인(NASA 이미지 라이선스·최적화, `next/image` `unoptimized`/스프라이트시트).
