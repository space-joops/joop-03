> 특히 `joop_03_game_config` 값을 게임이 실제로 읽지 않던 배선 문제를 함께 고쳤습니다.

## 의존성 / 순서 근거

- **M0가 모든 것의 선행.** 다만 M0 전체를 완성하지 않아도 M1은 착수할 수 있도록, M1이 실제로 필요한 M0 조각(디자인 토큰 최소본 + 데이터 계층 + i18n 기본 골격)만 먼저 갖춘다.
- **M1을 첫 화면으로 고른 이유**: 로그인 없이 볼 수 있어 데모 임팩트가 크고, 동시에 이 제품의 가장 독특한 기술 과제(**SSR 10초 좌표 스냅샷 + 클라이언트 동일 공식 보간**, [orbit-model](../architecture/orbit-model.md))를 초기에 검증한다.
- **관리자 파라미터화(E10)는 뒤로 미루되 부분 선반영**: 아케이드 물리(M5)와 궤도 주기(M1)에 설정값이 필요하므로, `joop_03_game_config` 읽기는 해당 마일스톤에서 함께 도입하고, 편집 UI만 M8로 미룬다.
- **아케이드(M5)가 기술적으로 가장 무겁다**: Canvas 2D 물리·입력·성능. 앞선 마일스톤에서 Canvas 렌더링(M1 궤도)과 지상 미니게임(M3) 조작을 먼저 다뤄 난이도를 계단식으로 쌓는다.

## 각 마일스톤 완료(Definition of Done) 공통 기준

- 해당 FR가 모바일 세로 화면에서 동작
- i18n 문자열은 dictionary 키로(하드코딩 금지), 영어 폴백 존재
- 배포 전 `package.json` 버전 범프 + 화면 버전 뱃지 확인([infra.md](../infra.md) 정책)
- 작업 로그(`docs/worklog/`)와 관련 문서 갱신
- PR 기반 병합(한국어)
