# 2026-07-27 · GTM 커스텀 이벤트(핵심 퍼널 통계) 추가

GTM 컨테이너/GA4 연결(이슈 #43 1~2단계, 사용자가 GTM 콘솔에서 직접 완료)이 끝난 뒤, 페이지뷰만으로는 이 게임의 핵심 퍼널(분양 → 지상 훈련 → 발사 청약 → 발사 → 아케이드)이 안 보인다는 문제로 이슈 #43의 3단계("후속 작업")를 실제로 구현했습니다.

## 문제 상황

`sendGTMEvent`(client-only)를 어디에 심을지 조사해보니, 게임의 핵심 서버 액션 7개 중 **2개(`redeemInvite`, `completeSetup`)는 성공 시 서버에서 바로 `redirect()`를 호출**해서, 호출한 클라이언트 컴포넌트가 성공 상태를 볼 기회 자체가 없었습니다. `useActionState`의 상태는 `redirect()`가 던지는 순간부터 그냥 페이지 이동으로 처리되고 절대 "성공" 값으로 갱신되지 않습니다.

## 결정

1. **`lib/analytics.ts` 신규** — 이 저장소의 `lib/minigame.ts`/`lib/space.ts` 스타일(작은 순수 함수 모음)을 따라, `sendGTMEvent`를 감싼 타입 있는 얇은 래퍼 함수들만 둠. `sendGTMEvent`의 `data: Object` 타입엔 컴파일 타임 안전성이 없어서, 여기서 함수 시그니처로 그걸 보완.
2. **리다이렉트형 2개는 일반적인 "flash message" 시스템을 새로 만들지 않고, 최소한의 1회성 쿼리 파라미터 신호만 추가**: `redeemInvite`는 `?src=invite`를 붙여 리다이렉트하고 도착 페이지(`setup-form.tsx`)가 마운트 시 한 번 확인 후 URL을 정리, `completeSetup`은 `?setup=done`을 붙이고 도착 페이지(`first-screen-client.tsx`)가 같은 패턴을 씀. `useRef` 가드로 React StrictMode의 이펙트 이중 실행에도 1회만 발화하게 함.
3. **PWA 설치 퍼널도 함께 포함**(원래 계획엔 "다음 라운드"로 미뤄뒀다가, 사용자 요청으로 이번에 포함) — `components/pwa-prompt.tsx`의 상태 갈래가 이미 깨끗해서(노출 3갈래/수락/닫기) 추가 비용이 적었습니다. 다만 "닫기"가 두 가지 다른 의미로 호출되고 있었다는 걸 코드를 읽으며 발견했습니다:
   - 명시적 "닫기" 버튼 클릭 → 진짜 닫음
   - `install()` 내부에서 네이티브 프롬프트 응답 후 정리용으로도 `dismissInstall()`을 호출 — 이건 수락이든 거절이든 무조건 불림

   그대로 두면 "설치 수락"도 "닫음"으로 잘못 잡히므로, `ev.userChoice`의 `outcome`을 받아 `outcome !== "accepted"`일 때만 `pwa_install_dismissed`를 쏘도록 분리했습니다(수락은 `appinstalled` 리스너의 `pwa_install_accepted`가 이미 잡음).

## 구현

- `lib/analytics.ts`(신규) — `trackLaunchBooked`, `trackLaunchCompleted`, `trackArcadeCompleted`, `trackMinigameCompleted`, `trackWaitlistJoined`, `trackInviteRedeemed`, `trackSetupCompleted`, `trackPwaInstallShown`, `trackPwaInstallAccepted`, `trackPwaInstallDismissed`.
- `app/[lang]/onboarding/actions.ts` — 성공 리다이렉트에 `?src=invite` 추가.
- `app/[lang]/onboarding/setup/actions.ts` — 성공 리다이렉트에 `?setup=done` 추가.
- `components/setup-form.tsx` / `components/first-screen-client.tsx` — 각각 마운트 시 1회 쿼리 확인 → 이벤트 발화 → `history.replaceState`로 URL 정리.
- `components/launch-list.tsx`, `components/launch-sequence.tsx`, `components/arcade-game.tsx`, `components/ground-minigame.tsx` — 각 서버 액션의 `res.ok` 분기에 트래킹 호출 삽입.
- `components/onboarding-form.tsx` — `waitState`에 걸린 `useEffect`로 `waitlist_joined` 발화(렌더 본문에 직접 두면 리렌더마다 재확인되므로 effect로 감쌈).
- `components/pwa-prompt.tsx` — 노출(최초 1회, `useRef` 가드)·수락(`appinstalled` 리스너)·닫음(명시적 버튼 vs 네이티브 프롬프트 거절 구분) 3개 이벤트.

## 이번엔 안 넣은 것

- 첫 화면 CTA 클릭, `level_up`(레벨업 감지에 "이번 판 이전 레벨"이 필요한데 `ground-minigame.tsx`가 그 값을 prop으로 안 받고 있어 서버 페이지까지 손대야 함) — 다음 라운드로.
- idle 자동 수거, 스플래시 스킵, 언어 전환 — 능동적 사용자 행동이 아니거나 저가치라 스킵.
- 초대 코드 공유 — 플레이어 화면에 그런 UI가 애초에 없음(관리자 콘솔에만 존재).

## 검증

- `npm run build` / `npm run lint` 통과. `installMode`(`"hidden" | "prompt" | "ios-safari" | "ios-other" | "generic"`) 타입이 `if (installMode === "hidden") return null;` 가드 이후 닫기 버튼의 `onClick` 클로저 안에서도 좁혀지는 것을 타입체크로 확인(별도 캐스팅 불필요).
- 각 삽입 지점이 정확한 성공 가드 안에 있는지, 응답 필드명이 맞는지 코드 트레이스로 확인.
- `npm run start`로 `/en` 접속 시 500이 뜨는데, 서버 로그로 원인이 "Supabase 환경변수가 없습니다"(이 샌드박스에 Supabase 자격증명이 없는 기존 제약, 이번 변경과 무관)임을 확인 — 새 코드가 별도의 런타임 오류를 내지 않는 것도 함께 확인.
- **이 세션에서 불가능한 것**: 실제 GTM Preview/GA4 DebugView 확인은 `googletagmanager.com`/`*.vercel.app` 접근이 막혀 있어 이 세션에서 못 함, 인증이 필요한 플로우(온보딩~발사~아케이드)도 Supabase 자격증명이 없어 이 환경에서 끝까지 못 타봄 — 배포 후 사용자가 GTM Preview 모드로 각 플로우를 직접 확인 필요.
