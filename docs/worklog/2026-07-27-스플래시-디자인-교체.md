# 인앱 스플래시를 디자이너 원본 디자인으로 교체 + 궤도 애니메이션

## 문제 상황

PR #40으로 인앱 스플래시(매 방문·2.8초·스킵)를 넣었지만 시각은 임시였다 — 로고 심볼 +
텍스트 워드마크 + 앰버 진행 바 + `BOOT SEQUENCE` 캡션. 정작 디자이너가 납품한 스플래시
디자인(`public/brand/splash-*.png`, iOS 네이티브 스플래시로만 쓰이던 것)과 전혀 달라서,
설치형 iOS에서 **네이티브 스플래시 → 인앱 스플래시**로 넘어갈 때 완전히 다른 화면이 떴다.

## 결정

### 1) 원본을 PNG가 아니라 인라인 SVG로 재현

마스터(`public/design-src/brand/splash-template.svg`, `design/m5-arcade`에서 반입 —
PNG 5종은 main에 있는데 마스터만 없던 상태)를 `components/splash-mark.tsx`로 포팅했다.

- **좌표를 마스터에서 그대로** 가져오고 `viewBox="0 0 1179 2556"` +
  `preserveAspectRatio="xMidYMid meet"`로 전체 화면에 얹는다. 폰 화면비(≈0.461)가 viewBox와
  사실상 같아 **네이티브 PNG와 배치가 그대로 겹친다**(엠블럼 = 화면 폭 72%·세로 42%,
  워드마크 = 폭 50%·세로 62% — 마스터 공식 그대로). 360폭·데스크톱에서는 여백이 생기지만
  배경색이 같아 이음매가 없다.
- PNG 대신 SVG라서 어떤 해상도에서도 선명하고, 무엇보다 **애니메이션이 가능**하다.

### 2) 색은 원본 팔레트 유지 (사용자 확정)

원본은 구 팔레트(`#05080a` / 그린 `#39ff14` / 앰버 `#ffb000`), 현재 앱 토큰은
(`#030a05` / `#35e07a` / `#ffb23e`). **원본 색을 그대로 쓰기로 확정** — 네이티브 스플래시
PNG와 완전히 일치해 설치형에서 전환이 매끄럽다. 앱 나머지 화면(민트 그린)과는 다르지만
스플래시는 브랜드 순간이라 허용. 대안(PNG 5종을 앱 토큰으로 재생성)은 선택하지 않았다.

### 3) "시계" 애니메이션 — 궤도 점 + 7-세그먼트

- **궤도 점 = 시계 바늘**(핵심): 앰버 링을 따라 도는 발광 점. 마스터가 링에 걸어둔
  `rotate(-24)`를 **부모 그룹으로 올려** 점의 궤도를 축정렬 타원으로 만든 뒤,
  `squash(ry/rx) → spin(t) → 점에서 counter-rotate(-t)·counter-scale(rx/ry)` 조합으로
  정확한 타원 운동을 만든다(점은 원형을 유지). 순수 CSS `transform`만 쓰므로
  `offset-path`/SMIL의 브라우저 편차나 JS 없이 `prefers-reduced-motion`을 media query로 처리할 수 있다.
  - **1회전 = 2.8초 = 스플래시 최소 노출 시간** → 한 바퀴 돌면 부팅 완료. 그래서 진행 바를
    없앴다(원본 디자인에도 없다). 기본 `transform`이 원본의 점 위치(로컬 각도 −35°)라
    **애니메이션이 꺼지면 그대로 원본 디자인**이 된다.
  - 좌표 검산: 로컬 (782.32, 443.17) → `rotate(-24 512 512)` → (730.96, 339.17) ≈ 마스터의 (731, 339) ✓
- **7-세그먼트 워드마크 = 디지털 시계**: 글자 5개가 0.13초 간격으로 순차 점등(총 ~0.8초).
  꺼진 세그먼트(opacity 0.1) 고스트 레이어는 원본대로 항상 표시.
- **글로우 호흡**: 발광 점 헤일로의 미세한 opacity 펄스.
- `prefers-reduced-motion`: 위 3가지 전부 정지 → 정지 화면이 곧 원본 디자인.

### 4) 워드마크는 로케일 고정

7-세그먼트 "JOOPS"는 path 로고타입이라 한국어("줍스")로 바뀌지 않는다. 네이티브 스플래시
PNG와 동일한 동작이고, 로케일 앱명은 컨테이너 `aria-label`로 스크린리더에 계속 전달된다.

## 검증

- `npx tsc --noEmit` / `npm run lint` / `npm run build` 통과
- Playwright(393×852) 시점별 스크린샷: t=250ms(점 우상단·글자 2개 점등) → t=1500ms(점이
  좌하단으로 공전·"JOOPS" 전부 점등)로 **궤도 운동과 순차 점등을 모두 확인**
- reduced-motion: 점이 원본 위치(우상단) 정지 + 워드마크 전부 점등 = 원본 디자인과 동일
- 원본 PNG 대조: 엠블럼 중심·워드마크 위치·점 위치가 계산값과 일치
- 360폭·데스크톱 폭에서 잘림 없음(배경색 동일이라 여백이 보이지 않음)
- PR #40 회귀: 2.8초 자동 종료 / 스킵 즉시 종료 / 리로드 재표시 모두 정상

### 5) 네이티브 스플래시 PNG 생성기를 저장소 안으로 (`gen:splash`)

`public/brand/splash-*.png` 5종은 M1 때 **레포 밖**(`/tmp/joops-assetgen`)에서 일회성으로
만든 산출물이라, 저장소 안에 재생성 경로가 없었다(아이콘·OG·게임 배경은 다 있는데 스플래시만
없던 상태). 마스터를 이번에 반입한 김에 워크로그(2026-07-26)에 문서로만 남아 있던
`splashSvg(w, h)` 공식을 `scripts/generate-splash.mjs`로 옮기고 `npm run gen:splash`를 추가했다.

- **리사이즈가 아니라 사이즈별 재조립**: iOS는 스플래시를 기기 해상도가 정확히 일치할 때만
  쓰므로, 한 장을 늘리면 업스케일 아티팩트가 생긴다. 해상도마다 SVG를 새로 만들어 벡터로 렌더한다.
  배치는 화면 비율 기준(엠블럼 폭 72%·세로 42%, 워드마크 폭 50%·세로 62%)이라 어떤 해상도에서도
  같은 구도가 나온다 — 마스터에 하드코딩된 `translate(589.5 1073.52) scale(1.3893)` 등도 이 공식의 결과다.
- **`<use>` 대신 path 를 직접 펼쳤다** — librsvg의 `href` 지원 편차를 피하려고. `<text>`·filter
  금지 규칙(handoff-m1)도 그대로 지킨다(글로우는 radialGradient 헤일로).
- **검증**: 재생성본을 기존 산출물과 픽셀 비교했다. 마스터 해상도(1179×2556)에서는 **32 이상
  차이 나는 픽셀이 0개**(최대 채널차 27 = 안티에일리어싱 반올림), 나머지 4종도 >32 차이가
  0.003% 수준(≈100픽셀)이고 전부 별의 서브픽셀 위치 차이다. 기하가 동일함을 확인.
- 부수 효과: 알파 채널이 빠져(전면 불투명이라 무해) 용량이 88~101KB → 38~44KB로 줄었다.

## 남은 것

- 스플래시 팔레트와 앱 토큰 팔레트가 갈라져 있다 — 통일하려면 마스터 색 교체 + `gen:splash`
  재실행 + `splash-mark.tsx` 색 교체가 함께 필요하다(이제 재생성이 가능하므로 언제든 할 수 있다).
- 기하가 마스터·스크립트·인앱 컴포넌트 3곳에 나뉘어 있다. 지금은 주석으로 동기화를 강제하지만,
  자주 바뀌면 공용 모듈로 뽑는 것이 낫다.
