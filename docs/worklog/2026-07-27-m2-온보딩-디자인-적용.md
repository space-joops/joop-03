# 2026-07-27 · M2 온보딩에 디자이너 시안 적용

## 무엇을 했나

디자이너가 [PR #10](https://github.com/space-joops/joop-03/pull/10)으로 납품한 **M2 온보딩 3단계 시안 + 줍스 캐릭터**를 코드에 적용했습니다. 온보딩 자체는 [PR #15](https://github.com/space-joops/joop-03/pull/15)에서 이미 동작하고 있었으므로, 이번 작업은 **기능 추가가 아니라 표현 계층 교체**입니다. 서버 로직(초대코드 검증·소진, 익명 세션, 분양 insert)은 한 줄도 바꾸지 않았습니다.

- 디자인 토큰을 **v1.0(디자이너 확정본)** 으로 전환 — `app/globals.css`
- 온보딩 3단계를 시안대로 재구성하고, **시안에는 있었지만 구현에 없던 ② 분양 연출(보급 카트리지 부팅)** 단계를 신설
- 줍스 캐릭터를 인라인 SVG 컴포넌트로 만들고 색 스와치와 연결
- **iOS 스플래시 5종 반입 + `appleWebApp.startupImage` 연결** (기존에는 미연결 상태였다)
- 검수용 개발 전용 라우트 `/[lang]/onboarding/preview` 추가 → 결과물: [onboarding-applied.png](../design/mockups/onboarding-applied.png)

## 왜 이렇게 했나 (문제 → 선택지 → 결정)

### 1. 토큰이 두 벌이었다

`main`의 `globals.css`는 PR #11에서 "확정"으로 머지된 팔레트(primary `#35e07a`, bg `#05070f`)를 쓰고 있었는데, 디자이너 시안·핸드오프는 전부 **토큰 v1.0**(primary `#39ff14`, bg `#05080a`, `--radius-sm` 4px, `--color-surface-raised`·`--glow-text`·베젤/모션 토큰 등)을 기준으로 작성돼 있었습니다. 시안대로 만들려면 없는 변수가 15개쯤 되고, 있는 변수도 값이 달랐습니다.

- (a) main 값을 유지하고 누락 토큰만 추가 → 구조는 시안과 같지만 색이 다름
- (b) 온보딩에만 v1.0을 지역 오버라이드 → 화면 간 색이 달라져 이동 시 브랜드가 튐
- (c) **v1.0으로 전환** ← 선택

디자이너 납품물이 정본이고, PR #11은 납품 전에 자체 제작한 임시본이라는 판단입니다. 대신 첫 화면·미니게임·발사 화면의 색이 함께 바뀌므로, 토큰 이름은 그대로 두고(기존 컴포넌트가 참조) **값만** 교체했습니다. `docs/design/design-tokens.md`도 v1.0으로 교체해 문서와 코드가 같은 것을 말하게 했습니다.

> 다음 사람을 위해: 지금 정본은 **디자이너 v1.0**입니다. PR #11 워크로그에 "확정"이라 적힌 구 값(`#35e07a` 등)은 이 커밋 이후 유효하지 않습니다.

### 2. 토큰 전환이 캔버스 두 곳을 조용히 망가뜨렸다

v1.0의 `--color-grid`는 `rgba(57,255,20,0.22)`로 **알파를 값에 내장**합니다. 그런데 `orbital-canvas.tsx`는 `ctx.globalAlpha = 0.55`, `ground-minigame.tsx`는 `0.18`을 겹쳐 곱하고 있었습니다. 그대로 두면 실효 알파가 0.12 / 0.04가 되어 지구본 그리드와 미니게임 배경 그리드가 사실상 사라집니다. 두 곳에서 `globalAlpha` 중첩을 제거했습니다(폴백 문자열도 새 팔레트로 갱신). 범위 밖 파일을 건드린 유일한 이유입니다.

### 3. 6칸 세그먼트 코드 입력을 포기했다

시안 ①의 핵심은 **6칸 계기판 입력**(48×56 셀, 도트매트릭스 글리프, 블록 캐럿)입니다. 그런데 DB에 시드된 초대코드는 `JOOP-ALPHA-01` — 하이픈 포함 13자라 6칸에 들어가지 않습니다.

- (a) 6자 코드 체계로 바꾸고 6칸 입력 구현 → 마이그레이션 필요(이번 작업은 공유 DB 쓰기 금지)
- (b) **기존 형식 유지 + 콘솔 필드 1개** ← 선택

대신 계기판 느낌은 살렸습니다: 콘솔 필드에 `--font-display`(Doto 도트매트릭스) + 자간 + 형광색 + 자동 대문자를 적용했습니다. 코드 체계를 6자로 정리하면 시안 그대로 갈 수 있으므로 [ADR-0004](../architecture/adr/0004-auth-invite.md) 미해결 항목에 남겼습니다.

### 4. 블록 캐럿을 직접 그리지 않았다

시안은 입력 필드에 형광 블록 캐럿(10×22)을 그립니다. 이걸 재현하려면 투명 input 위에 값을 `<span>`으로 복제해야 하는데, **한글 IME 조합 중에는 조합 문자가 `value`에 없어서 글자가 보이지 않습니다.** 줍스 이름은 한글이 주 케이스라 치명적입니다. 그래서 실제 `<input>`을 쓰고 `caret-color: var(--color-primary)` + `caret-shape: block`(지원 브라우저에서만 블록)으로 낮췄습니다. 점멸 여부는 OS 접근성 설정을 자동으로 따릅니다. 디자이너 확인이 필요한 유일한 시각적 후퇴입니다.

### 5. 부팅 연출은 타이머 2개가 아니라 rAF 클럭 1개로

② 는 12칸 바를 3초에 채우면서 부팅 로그를 0.8초 간격으로 한 줄씩 띄웁니다. `setInterval` 두 개를 쓰면 서로 어긋나고 탭이 백그라운드로 가면 밀립니다. `performance.now()` 기준 rAF 하나에서 두 값을 파생시키면 항상 동기화되고, 탭에 돌아왔을 때 경과 시간에 맞는 위치로 바로 점프합니다. `prefers-reduced-motion`이면 rAF를 아예 시작하지 않고 즉시 100% + 로그 일괄 표시(핸드오프의 대안 그대로).

③에서 뒤로 가면 ②가 다시 재생되는 문제는 `sessionStorage` 완료 플래그로 막았습니다(브라우저 뒤로가기에도 동작).

### 6. 캐릭터 색이 안 바뀌던 버그

`JoopCharacter`에 `className="text-[var(--joop-accent)]"`를 줬는데 색이 적용되지 않았습니다. Tailwind v4는 대괄호 임의값의 타입(색 vs 폰트 크기)을 추론해야 하는데, `--joop-accent`는 `--color-*` 네임스페이스가 아니어서 **규칙 자체가 생성되지 않았고**, `color`가 `--color-fg`로 상속돼 눈·입이 흰색으로 나왔습니다. `style={{ color: "var(--joop-accent)" }}`로 바꿔 해결했습니다. 시안 검수 스크린샷을 실제로 찍어보지 않았으면 놓쳤을 버그입니다(스크린샷상 그린 계열이라 눈에 잘 안 띔).

액센트를 쓰는 다른 곳도 확인했습니다 — `--color-*` 이외의 변수를 대괄호 임의값 색으로 쓰는 곳은 없습니다.

### 7. 이 워크로그가 CSS 빌드를 깨뜨렸다

위 항목을 쓰면서 본문에 대괄호 임의값 예시를 말줄임표(`…`)와 함께 적었더니, **Tailwind 가 그 문자열을 클래스 후보로 스캔해 `color: var(…)` 같은 잘못된 규칙을 생성했고 CSS 파싱이 실패**했습니다(`Unexpected token Ident("…")`). Tailwind v4 는 기본적으로 프로젝트 전체(`.gitignore` 제외)를 훑기 때문에 `docs/**/*.md` 의 코드 예시도 스캔 대상입니다.

빌드가 통과한 시점 이후에 워크로그를 썼기 때문에 커밋 직전 검증에서 잡히지 않았고, 스크린샷을 다시 찍으려고 dev 서버를 띄웠을 때 500 으로 드러났습니다.

- (a) 문서에서 문제 문자열만 고친다 → 같은 일이 반복된다(문서에 코드 예시를 계속 쓴다)
- (b) **스캔 범위를 소스로 한정한다** ← 선택

`app/globals.css` 를 `@import "tailwindcss" source(none);` + `@source "../app" / "../components" / "../lib"` 로 바꿨습니다. 문서가 CSS 빌드를 깨뜨릴 수 없게 되고, 스캔 대상이 줄어 빌드도 약간 가벼워집니다. 문서 문구도 함께 다듬었습니다.

교훈: **문서를 쓴 뒤에도 빌드를 한 번 더 돌린다.** 이 리포에서 `docs/` 는 빌드 입력이다.

### 8. iOS 스플래시가 미연결이었다

디자이너는 스플래시 5종(`public/brand/splash-*.png`, 마스터 `splash-template.svg`)을 이미 납품했는데, `main`에는 파일도 없고 `appleWebApp.startupImage`도 비어 있어 **설치형에서 흰 화면이 뜨는 상태**였습니다. 파일을 반입하고 [handoff-m1.md](../design/handoff-m1.md) §3-2의 media 쿼리를 그대로 연결했습니다.

iOS는 **기기 해상도가 정확히 일치할 때만** 스타트업 이미지를 쓰고 아니면 무시하기 때문에 기기별 5종이 필요합니다(390×844 / 393×852 / 402×874 / 430×932 / 440×956, 모두 DPR 3). 안드로이드는 매니페스트의 아이콘 + `background_color`로 자동 생성하므로 파일이 필요 없습니다 — 그 값도 이번에 `#05080a`로 맞췄습니다.

스플래시 템플릿이 v1.0 팔레트(`#39ff14` · `#05080a`)로 그려져 있어서, **토큰을 v1.0으로 전환한 이번 작업과 함께 넣어야 색이 맞습니다**(구 팔레트 상태로 넣었다면 앱 첫 화면과 스플래시 색이 어긋났습니다).

한편 같은 핸드오프 §3-2는 `viewportFit: "cover"`도 요구하는데, 이건 첫 화면·M3 화면의 여백까지 바꾸고 실기기 없이는 확인할 수 없어 이번 범위에서 뺐습니다(아래 한계 참조).

### 9. 캐릭터 시안이 두 벌이 되었다

PR #16(머지됨)이 넣은 `public/game/joop-{green,amber,cyan}.svg`(다크 네이비 셸, 3색, 상태 프레임 없음)와 PR #10의 크림 CRT 셸(6색 × 3상태 스프라이트 시트)이 **서로 다른 캐릭터**입니다. 온보딩은 지시대로 PR #10 캐릭터를 씁니다(6색 팔레트·스와치·스프라이트 시트가 모두 맞물림). PR #16 자산은 지우지 않고 남겨두고, 에셋 인벤토리에 A안/B안으로 나란히 적어 **디자이너가 하나를 확정하고 나머지를 폐기**하도록 했습니다.

### 10. 검수를 위해 개발 전용 라우트를 만들었다

②③은 세션 가드가 있어서 실제로 보려면 초대코드를 소진하고 익명 사용자를 만들어야 합니다(= 공유 DB 쓰기). 디자인이 어떻게 적용됐는지 보려고 그 비용을 치를 이유가 없어서, 같은 컴포넌트를 스텁 props로 렌더하는 `/[lang]/onboarding/preview`를 만들었습니다(운영에서는 `notFound()`). `?boot=complete`로 연출 완료 상태, `?w=360`으로 좁은 폭을 볼 수 있습니다. 이 라우트를 병합 전에 뺄지는 리뷰에서 결정하면 됩니다.

## 검증

- `npx tsc --noEmit` · `npm run lint` 통과
- `npm run build`: 컴파일·타입체크 통과, 정적 페이지 16/22 생성 후 **`/api/orbital` 프리렌더에서 실패**. 원인은 로컬에 `.env.local`이 없어 Supabase 환경변수가 비어 있는 것이고, `origin/main`을 그대로 빌드해도 **같은 지점에서 같은 이유로 실패**합니다(이번 변경과 무관한 기존 조건). 더미 환경변수를 넣으면 실패가 DNS 오류로만 바뀝니다.
- 시각 검수(`/ko|en/onboarding/preview`, 393×852 및 360폭): 치수·색·폰트를 시안과 비교. 결과 이미지 3장
  - [onboarding-applied.png](../design/mockups/onboarding-applied.png) — 한국어 3단계(② 는 연출 중간 9/12)
  - [onboarding-applied-swatch-magenta.png](../design/mockups/onboarding-applied-swatch-magenta.png) — 색 교체 후 캐릭터 액센트
  - [onboarding-applied-reduced-motion-en.png](../design/mockups/onboarding-applied-reduced-motion-en.png) — 모션 최소화 + 영문
- 부팅 연출: 실제 브라우저에서 중간 프레임 9/12 + `만나기` 비활성 → 3초 후 12/12 + `부팅 완료` + 활성 확인
- 모션 최소화(`--force-prefers-reduced-motion`): 진입 즉시 12/12 + 로그 3줄 동시 + CTA 활성
- 스와치: magenta 클릭 시 `--joop-accent`가 `#39ff14` → `#ff2e97`로 바뀌고 캐릭터 눈·입·안테나·LED·바닥 글로우가 함께 변경, `aria-checked`는 하나만 true
- 폰트: 초대코드 필드·`JOOP-0042`는 Doto(도트매트릭스), 이름 필드는 Geist Mono. **한글에는 display 폰트가 적용되지 않음** 확인
- 스플래시: `<link rel="apple-touch-startup-image">` 5개가 media 쿼리와 함께 생성되는지, 각 PNG가 HTTP 200 이며 파일명의 해상도와 실제 픽셀이 일치하는지 확인(1170×2532 · 1179×2556 · 1206×2622 · 1290×2796 · 1320×2868). **실기기 설치 후 표시 확인은 못 했습니다**

## 알려진 한계 / 다음

- **종단 플로우 미검증**: 실제 코드 소진 → 부팅 → 이름·색 저장 → 첫 화면 "내 줍스"는 공유 DB(jd-04) 쓰기가 필요해 이번 작업에서 실행하지 않았습니다. 배포도 하지 않았습니다.
- **줍스 색 팔레트 불일치**: 스와치는 디자이너 팔레트(`lib/joop-colors.ts` ← `joop-sheet.meta.json`)를 쓰지만, M1 시드 NPC 100개의 `color`는 구 hex(`#00e5ff` 등)입니다. 첫 화면 궤도 점과 온보딩 스와치의 색 세트가 다릅니다 → 데이터 정합화는 마이그레이션이 필요한 별도 작업.
- **브랜드/PWA 아이콘이 구 팔레트**: UI는 `#39ff14`인데 `public/brand/*.svg`·`public/icon-*.png`는 `#35e07a`로 그려져 있습니다. 마스터 SVG를 v1.0으로 다시 그려 `npm run gen:icons` 하는 별도 작업이 필요합니다.
- **`viewportFit: "cover"` 미적용**(스플래시와 같은 핸드오프 §3-2 항목): `--safe-top/--safe-bottom`은 `max(env(...), 12px)`라 지금도 12px 하한으로 동작하지만, 노치 기기에서 실제 인셋을 받으려면 루트 레이아웃에 `viewportFit: "cover"`가 필요합니다. 첫 화면 여백이 함께 바뀌는 변경이라 이번 범위에서 뺐습니다.
- 순수 로직(`deviceNameFor`, 색 검증, 부팅 클럭)이 늘었지만 테스트 인프라가 없어 검증이 수동뿐입니다. vitest 도입을 제안합니다.
