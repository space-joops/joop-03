# 2026-07-27 · 지상 훈련 미니게임 전면 개편 (식별 훈련) + 테스트용 레벨 완화

M3에서 만든 지상 미니게임을 **방식부터 다시** 만들었습니다. "공중에서 분사로 날아다니며 쓰레기 먹기" → **"땅에 서서 좌우로만 움직이며, 받아도 되는 쓰레기와 부딪히면 안 되는 위성을 식별하기"**. 그리고 테스트 중에는 발사까지 빨리 가볼 수 있게 레벨 곡선을 완화했습니다.

## 문제 상황

기획자(사용자)가 지적한 세 가지입니다.

1. **"지금처럼 화면 위에만 있는 게임은 이상하다."**
   두 가지 의미가 겹쳐 있었고, 둘 다 사실이었습니다.
   - 연출: "지상 훈련"인데 줍스가 땅에 발을 붙이지 않고 화면 가운데 공중에 떠 있었습니다.
   - **버그**: 게임 캔버스가 실제로 **화면 위쪽 1/4 정도만** 차지하고 있었습니다. 캔버스에 `class="h-full"`(=`height:100%`)을 줬는데, `canvas`는 `width`/`height` 속성에서 오는 **고유 종횡비**를 가진 대체 요소(replaced element)라서 흐름 배치에서는 그 종횡비가 이겨 366×182로 눌려 있었습니다(컨테이너는 366×744). 즉 "게임이 화면 위에만 있다"는 말은 은유가 아니라 그대로였습니다.
2. **방식을 바꿔 달라 — 먹어도 되는 쓰레기와 충돌하면 안 되는 것을 식별하는 훈련으로.**
   기존 게임은 화면의 모든 물체가 "먹으면 점수"라서 판단할 것이 없었습니다. 조작 학습(FR-3.1)만 있고, 궤도에서 실제로 필요한 "무엇을 주워도 되는가"라는 판단은 훈련되지 않았습니다.
3. **캐릭터가 나와서 유대를 쌓는 훈련으로.**
   플레이어가 조작하는 것이 색깔 있는 원 하나였습니다. 애착의 대상이 되기 어렵습니다.
4. **테스트 개발 중이니 쉽게 발사까지 가게 해 달라.**
   기존 값으로는 Lv.3(=200XP)까지 쓰레기 25개, Ariane 6(Lv.4)은 38개를 먹어야 했습니다. 발사·궤도·지도 흐름을 반복 검증하기에 너무 느렸습니다.

## 무엇을 어떻게 바꿨나

### 게임 방식 — 좌우 이동 + 식별

- 줍스는 **땅 위에 서서 좌우로만** 이동합니다(FR-3.1a). 조작은 화면을 좌우로 끌기(모바일) 또는 `←`/`→`·`A`/`D`(데스크톱).
- 위에서 물체가 떨어집니다(FR-3.1b).
  - **받아내기**: 우주 쓰레기 6종(캔·볼트·패널·회로·안테나·위성 파편) → 수거 +1, 유대 상승
  - **피하기**: 작동 중인 위성 2종(통신위성·탐사선) → 내구도 −1, 유대 하락
- 종료 조건은 **제한 시간(기본 60초) 또는 내구도 소진(기본 3회)**. 예전의 "분사가스 소진"(FR-7.6)은 분사가 없어졌으니 함께 사라졌습니다.
- 난이도는 시간에 비례해 올라갑니다(낙하 속도↑, 생성 간격↓ — 하한 0.28초).

**"위성 파편은 쓰레기, 작동 중인 위성은 위험물"** 이라는 구분이 이 훈련의 핵심입니다. 실루엣만으로 순간 판단하기 어려울 수 있어, 위험물에는 **붉은 기운 + 깜빡이는 경고등**을, 쓰레기에는 앰버 기운을 입혔습니다. 완전히 색으로 정답을 알려주면 훈련이 아니게 되고, 아무 단서도 없으면 작은 화면에서 불공평해집니다 — 그 중간을 택했습니다. 시작 전 브리핑 화면에서 두 부류의 아이콘을 **정답표로 먼저 보여줍니다.**

### 캐릭터와 유대

- 줍스를 캔버스에 직접 그렸습니다(카세트퓨처리즘 청소로봇: 무한궤도 · 바이저 · 앰버 비콘 · 수거 바스켓). 액센트 색은 온보딩에서 고른 **내 줍스 색**입니다.
  - SVG 에셋(`public/game/joop-*.svg`)은 green·amber·cyan 3종뿐이고 사용자 색은 6종이라 그대로 쓸 수 없었습니다. 무엇보다 **표정 변화**가 필요해서(받아내면 `^^`, 부딪히면 `××` + 흔들림, 가끔 눈 깜빡임, 이동 방향으로 눈동자 쏠림) 코드로 그리는 쪽을 택했습니다. 떨어지는 물체는 반대로 디자인 에셋(SVG)을 그대로 씁니다 — 실루엣 구분이 생명인 부분이라 잘 만든 에셋이 유리합니다.
- **유대(0~100)** = `수거×5 − 충돌×12`. HUD에 바로, 결과 화면에 등급으로("아직 낯가려요 → 친해지는 중 → 든든한 동료 → 한 몸처럼") 보여줍니다.
  - 지금은 **연출이고 DB에 남기지 않습니다.** 영속화하려면 스키마·랭킹 정의가 필요해서 인벤토리(EPIC 8)와 함께 다루는 것이 맞다고 판단했습니다. XP는 종전대로 **서버가 수거 개수로만** 계산합니다(치팅 방어선 유지).

### 캔버스 크기 버그

두 곳을 고쳤습니다.

- 캔버스를 `absolute inset-0 h-full w-full`로 컨테이너에 꽉 채웁니다. 고유 종횡비가 개입할 여지를 없앱니다.
- `ResizeObserver`로 크기를 따라갑니다. 기존에는 `window resize`만 들어서, 레이아웃 확정 전에 한 번 잘못 잰 크기를 끝까지 들고 갔습니다.

> ⚠️ 함정 기록: 처음에는 `absolute inset-0`만 주고 **캔버스 자신의 rect**를 재서 `canvas.width`에 다시 썼습니다. 절대 배치된 대체 요소는 `width:auto`면 고유 크기를 쓰기 때문에 `rect → width 속성 → 고유 크기 → rect` 되먹임이 생겨 캔버스가 매 관측마다 커지고 **탭이 크래시**했습니다. 지금은 크기를 **컨테이너에서** 재고, 캔버스에는 `h-full w-full`을 함께 줍니다.

### 운영 파라미터 교체 (EPIC 10)

의미가 완전히 달라져 재해석 대신 키를 교체했습니다.

| 제거 | 추가 |
| --- | --- |
| `minigame_thrust` · `minigame_max_speed` · `minigame_fuel` · `minigame_friction` | `minigame_move_speed` · `minigame_fall_speed` · `minigame_fall_ramp` · `minigame_spawn_interval` · `minigame_hazard_ratio` · `minigame_lives` · `minigame_duration_seconds` |

`minigame_xp_per_debris` · `minigame_max_debris_per_run`은 그대로 둡니다. 제거한 키는 마이그레이션에서 **DB에서도 지웁니다** — 레지스트리(`lib/config-specs.ts`)에서만 빼면 관리자 콘솔의 "레지스트리에 없는 키"에 영구히 남아 운영자를 혼란스럽게 합니다.

관성·분사 물리 함수(`applyThrust` 등)는 삭제했습니다. 아케이드(M5)는 여전히 5원 조이스틱 + 관성이 요구사항(FR-7.4/7.5)이지만, 아직 쓰이지 않는 코드를 "나중에 쓸지도 모른다"고 남겨두면 죽은 코드가 됩니다. 필요해지면 그때 그 화면의 요구에 맞춰 다시 세우고, 지금은 git 이력에 맡깁니다.

### 테스트용 난이도 완화 (되돌릴 값)

- `minigame_xp_per_debris` **8 → 25**: 4개만 받아내도 Lv.2, 8개면 Lv.3.
- `launch_required_level`(새 발사체 기본값) **3 → 1**.
- 시드된 발사체의 `required_level`을 **최대 2로** 눌렀습니다. 전부 1로 만들지 않은 이유는 "필요 레벨 미달" 게이팅 UI를 계속 확인할 수 있어야 하기 때문입니다.

⚠️ **정식 운영 전에 되돌려야 하는 값입니다.** 관리자 콘솔에서 조정할 수 있고, `supabase/rollback_joop_03_ground_training_rework.sql`에 원복 SQL을 남겨 두었습니다.

## 요구사항 문서에 남긴 변화

지상은 좌우 이동, 아케이드는 자유 이동 + 조이스틱이 되어 **FR-7.1의 "동일 조작"이 깨졌습니다.** 숨기지 않고 requirements.md의 FR-7.1에 경고 주석으로 적었습니다. 지상에서 배우는 것은 조작이 아니라 **식별**이라고 보고 갈라짐을 받아들였으며, M5 착수 시 "동일 조작"의 의미를 다시 정의합니다. EPIC 3에는 FR-3.1a/b/c(좌우 이동 · 식별 · 캐릭터와 유대)를 세부 항목으로 추가했습니다.

## 검증

- `npm run build` · `npm run lint` 통과.
- 로컬 dev + Chromium(Playwright, 390×780)으로 실제 플레이 확인:
  - 시작 브리핑(정답표) → 플레이 → 시간 종료 / 내구도 소진 두 결말 모두 결과 화면 정상.
  - 캔버스가 컨테이너 전체를 채우고, 줍스가 땅에 서 있고, 드래그·화살표 키 이동 모두 동작.
  - 받아내기 `+1` 플로터 · 웃는 눈, 충돌 `!` · `××` 눈 + 흔들림 · 붉은 외곽선 확인.
- 마이그레이션은 공유 프로젝트라 Management API로 적용 필요(스키마 변경 없음 — `joop_03_game_config` 값과 `joop_03_launch_vehicles.required_level`만 바뀝니다).

## 알려진 한계 / 다음

- **유대가 저장되지 않습니다.** 판이 끝나면 사라집니다. 영속화·성장 반영은 EPIC 8과 함께.
- 밸런스(위험물 비율 0.35 · 난이도 상승 계수 0.012)는 감으로 잡은 값입니다. 실제 플레이 로그를 보고 조정해야 합니다.
- 놓친 쓰레기에 대한 벌칙이 없습니다. "안 움직이고 위성만 피하기"가 안전하지만 그러면 XP가 0이라 자연히 억제됩니다 — 벌칙을 추가할지는 플레이 감각을 보고 판단.
- 접근성: 위험물 판단이 색(붉은 기운)에 일부 의존합니다. 실루엣만으로도 구분되게 위성 에셋을 더 크게/다르게 갈지 검토 필요.
- `prefers-reduced-motion` 대응 없음(첫 화면에는 있음).
