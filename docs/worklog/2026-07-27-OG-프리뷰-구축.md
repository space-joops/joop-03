# 2026-07-27 · OG(Open Graph) 링크 프리뷰 구축

`https://joop-03.vercel.app` 링크를 슬랙/카카오톡/트위터(X)/문자로 공유했을 때 미리보기 이미지·설명이 뜨도록 만들었습니다. 요청은 "일단은 쉬운 영어로 설명과 이미지 만들어서 공유되게" — 이슈 #35가 지적한 전체 다국어 메타데이터 정비가 아니라, 지금 당장 링크를 공유했을 때 보기 좋은 프리뷰가 뜨는 것이 목표였습니다.

## 문제 상황

`app/[lang]/layout.tsx`에 정적 `metadata`(한국어 고정)만 있었고 `openGraph`/`twitter` 필드, OG 이미지 관련 코드는 저장소 전체에 전무했습니다(grep 0건). `/en`을 방문해도 한국어 title/description이 나가는 상태였습니다(이슈 #35의 1번 항목과 동일 지점).

## 이 포크의 Next.js 문서 확인

이 저장소는 표준 Next.js와 다른 커스텀 포크라 `AGENTS.md`가 코드 작성 전 `node_modules/next/dist/docs/` 확인을 요구합니다. `npm install` 후 확인해보니 — **`opengraph-image`/`twitter-image` 파일 기반 컨벤션과 `next/og`의 `ImageResponse`는 표준 Next.js와 동일하게 동작**했습니다(`node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/01-metadata/opengraph-image.md`). 특히 이미지를 코드로 생성(`ImageResponse`)할 필요 없이, `app/[lang]/opengraph-image.jpg` 처럼 **정적 이미지 파일을 그 경로에 두기만 해도** Next가 `og:image` 등 태그를 자동으로 주입합니다.

## 선택지

1. **`ImageResponse`로 코드에서 동적 생성** — 브랜드 폰트(Geist)를 Satori에 별도 바이트로 전달해야 하고, `public/brand/logo-wordmark-phosphor.svg`의 CRT 글로우 필터(`feGaussianBlur`)는 Satori가 지원하지 않아 재현이 번거로움.
2. **정적 이미지 파일을 그대로 배치** — 사용자가 이미 "JOOPS UNIT" 로봇 일러스트를 제공했고, "일단은 간단하게"가 목표라 코드 생성보다 훨씬 빠르고 확실함.

**2번으로 결정.** 다만 원본 이미지가 1284×1102(거의 정사각형)라 OG 권장 비율(1200×630, 1.91:1)과 맞지 않았습니다. 크롭하면 로봇 일부가 잘릴 위험이 있어, 원본 배경이 단일 밝은 회색(`#cfcfcd`)인 점을 이용해 **높이를 630에 맞춰 축소한 뒤 같은 회색으로 좌우를 패딩**해 1200×630을 만들었습니다(이음매가 안 보임).

## 구현

- `public/design-src/og/joops-cover-source.jpg` — 사용자가 제공한 원본 일러스트(소스, 커밋 대상).
- `scripts/generate-og-image.mjs` — 기존 `scripts/generate-icons.mjs` + `sharp` 패턴을 그대로 따라 소스를 1200×630으로 가공해 `app/[lang]/opengraph-image.jpg`·`twitter-image.jpg`로 출력. `package.json`에 `"gen:og"` 스크립트 추가.
  - ⚠️ **삽질 기록**: sharp 파이프라인에 `.resize()`를 두 번 체이닝했더니(축소 → `.extend()`로 패딩 → 다시 `.resize()`로 "보정") 최종 폭이 1666px로 나왔습니다. sharp는 여러 `resize()` 호출을 순서대로 적용하지 않고 **내부적으로 고정된 파이프라인 순서**(resize 다음 extend)로 처리하기 때문에, 뒤에 호출한 resize가 앞의 것을 덮어쓰고 extend가 그 위에 다시 적용된 것이었습니다. `toBuffer()`로 각 단계를 실체화해 체이닝을 끊자 해결됐습니다. 다음에 sharp로 "축소 후 패딩" 같은 다단계 가공을 할 땐 각 단계를 버퍼로 끊을 것.
- `opengraph-image.alt.txt` / `twitter-image.alt.txt` — 로봇 일러스트에 대한 영문 alt 텍스트.
- `lib/i18n/dictionaries/{en,ko}.json` — `meta` 네임스페이스 신설(`title`/`description`). 영어는 쉬운 표현("Adopt a space robot and help clean up Earth's orbit. Play free in your browser."), 한국어는 기존 `metadata.title`에 있던 문구를 그대로 이관해 한국어 사용자 경험은 변화 없음.
- `app/[lang]/layout.tsx` — 정적 `metadata` export를 `generateMetadata({ params })`로 전환. `dict.meta`에서 title/description을 읽어와 `metadataBase`(`https://joop-03.vercel.app`) + `openGraph`(locale별 `ko_KR`/`en_US`) + `twitter`(`summary_large_image`) 블록을 추가. 파일 기반 이미지 컨벤션이 `og:image`/`twitter:image`를 자동 주입하므로 `images` 필드는 명시하지 않음.

## 검증

`npm run build` 후 `npm run start`로 로컬 확인:
- `/en`, `/ko` 각각 렌더된 `<head>`에서 `og:title`/`og:description`/`og:image`(절대 URL)/`twitter:card` 등이 로케일에 맞게 정확히 박히는 것을 확인.
- 이미지 라우트(`/-/opengraph-image.jpg?...`)가 실제로 200 + `image/jpeg`로 응답하고, 1200×630 크기가 맞는 것을 확인.
- `/` → `/en` 307 리다이렉트 확인(`proxy.ts` 로케일 처리).

**참고**: 이 환경(Supabase env 미설정)에서 `/en`을 직접 열면 데이터 조회 실패로 500이 뜨는데, 이건 메타데이터/OG와 무관하게 이미 있는 이슈 #32("에러 경계 전무")입니다. `generateMetadata`는 페이지 본문의 데이터 조회와 독립적으로 먼저 해석되므로, 본문이 500이어도 `<head>`의 OG 태그 자체는 정상적으로 내려가는 것도 함께 확인했습니다(실제 배포 환경은 Supabase 자격증명이 있으므로 이 500은 재현되지 않습니다).

실제 배포된 `https://joop-03.vercel.app`에서 페이스북/트위터/카카오 언퍼널 디버거로 최종 검증하는 것은 이 세션의 네트워크 정책이 `*.vercel.app`을 막고 있어 불가능했습니다(과거 워크로그에 이미 기록된 제약). 배포 후 실제 공유로 확인이 필요합니다.

## 범위 밖으로 남긴 것

- 이슈 #35의 나머지 항목(핀치 줌 차단, 폼 라벨/캔버스 aria, hreflang alternates, 로케일별 `manifest.ts`)은 이번에 건드리지 않았습니다.
- OG 이미지는 로케일 무관 단일 영어 버전 하나만 만들었습니다("일단은 쉬운 영어로"라는 요청에 맞춤).
