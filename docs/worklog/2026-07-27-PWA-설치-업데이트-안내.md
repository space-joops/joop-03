# PWA 설치 안내 배너 + 배포 업데이트 안내

## 문제 상황

PWA 매니페스트는 갖춰졌지만(ADR-0002), 사용자를 설치로 이끄는 장치가 전혀 없었다.
특히 iOS는 브라우저가 설치 프롬프트를 제어할 수 없어서, 안내 없이는 사용자가 홈 화면
추가 경로를 스스로 찾아야 한다. 또 배포가 수동(vercel deploy --prod)이고 서비스워커가
없어서, 설치형(standalone) 사용자는 앱을 껐다 켜기 전까지 구버전에 머물 수 있는데
새 배포를 알려줄 방법이 없었다 — ADR-0002에 "업데이트 알림(후속)"으로 예고만 있던 상태.

## 선택지와 결정

### 1) 새 배포를 어떻게 감지하나

- A. 서비스워커 도입 (updatefound 이벤트)
- B. **`/api/version` 폴링** ← 채택

SW는 ADR-0002가 Turbopack↔Serwist 충돌로 의도적으로 미룬 상태고, 이번 요구(업데이트
안내)만으로 뒤집을 이유가 없다. `package.json` 버전이 빌드타임에 인라인되는 점을 이용해
클라이언트 상수와 `/api/version`(no-store) 응답을 **단순 불일치 비교**한다. 버전은 단조
증가라 semver 파싱도 불필요. 설치형에서만 5분 폴링 + 탭 복귀(visibilitychange) 시 즉시
체크. 매니페스트에 버전을 심는 방법은 검토 후 기각 — 번들 Next 가이드(manifest.md)에
따르면 manifest.ts는 기본 정적 캐시되는 특수 라우트라 감지 채널로 부적합하다.

**주의: 버전 범프 없이 배포하면 안내가 뜨지 않는다.** infra.md 배포 체크리스트에
이 사실을 명시했다.

### 2) 업데이트 적용 방식

- A. 감지 즉시 자동 새로고침
- B. **안내 창 + '업데이트' 버튼** ← 채택 (사용자 확정)

미니게임·발사 시퀀스 도중 강제 리로드는 진행 손실이라, 사용자가 시점을 선택한다.
SW 캐시가 없으므로 `location.reload()`만으로 새 빌드를 받는다.

### 3) 설치 안내 UX

- 요구사항: iOS처럼 제어 불가면 친절한 수동 안내, 가능하면 바로 설치 버튼.
- **iOS Safari**: 공유 버튼 → "홈 화면에 추가" → "추가" 3단계 안내.
- **iOS 타 브라우저**(CriOS/FxiOS/EdgiOS/NAVER/Whale 등 UA 토큰): "Safari로 열면
  금방이에요" + 주소 복사 → Safari 접속 → 홈 화면 추가 3단계.
- **그 외**: `beforeinstallprompt` 캡처 → "앱 설치" 원탭 버튼. 번들 Next 가이드는
  크로스브라우저가 아니라며 비권장하지만, iOS를 위처럼 별도 커버하므로 **의도적
  채택**(ADR-0002 추기에 근거 기록). 3초 내 미발화면(Firefox Android 등) 브라우저
  메뉴 일반 안내로 폴백하고, 늦게 발화하면 버튼형으로 승격.
- iPadOS 13+가 데스크톱 UA로 위장하는 문제는 `MacIntel + maxTouchPoints > 1`로 판별.
- 노출 정책(사용자 확정): **매 방문마다 표시**, 닫기는 sessionStorage로 해당 세션만 숨김.
- 두 UI는 standalone 게이트로 상호배타 — 설치 배너는 `!standalone`, 업데이트 폴링은
  `standalone`에서만.

### 4) 배치

`app/[lang]/layout.tsx` body에 마운트 → 게임 전 페이지 적용, admin 트리(별도 루트
레이아웃)는 제외. 레이아웃이 `getDictionary(lang)`를 호출해 **`dict.pwa` 슬라이스만**
prop으로 내린다(전 페이지를 감싸므로 payload 최소화). 배너는 CRT 투톤 규칙을 따르는
하단 고정 `.panel-amber` 패널(앰버 제목 + primary CTA), z-50.

## 검증

- `tsc --noEmit` / `npm run lint` / `npm run build` 통과 (react-hooks/set-state-in-effect
  규칙에 걸린 iOS 분기 동기 setState는 0ms 타이머로 비동기화).
- Supabase 없는 임시 프리뷰 라우트(커밋 안 함) + Playwright로 6케이스 확인:
  iOS Safari 3단계 / iOS 크롬 Safari 유도 / BIP 합성 발화 → 설치 버튼 / 미발화 3초 →
  generic 폴백 / standalone(+ `/api/version` mock 99.0.0) → 업데이트 창 + 버튼 클릭 시
  리로드 / 닫기 → 같은 세션 재노출 없음.
  - 팁: CDP `Emulation.setEmulatedMedia`의 display-mode 에뮬레이션이 이 Chromium에서
    동작하지 않아, `matchMedia` init script 오버라이드로 standalone을 시뮬레이션했다.
- 배포 후 실기기 확인 절차: iOS Safari에서 안내 노출 → 설치 → standalone에서 배너
  미노출 확인 → 다음 버전 범프 배포 후 앱 재진입(또는 탭 복귀) 시 업데이트 창 확인.

## 남은 것 / 알려진 한계

- 안드로이드에 이미 설치된 상태로 브라우저 탭 접속 시 BIP가 발화하지 않아 generic
  안내가 노출될 수 있음 (`getInstalledRelatedApps`는 매니페스트 related_applications
  필요라 범위 외).
- iOS 16.4+ 일부 타 브라우저는 실제로 홈 화면 추가가 가능하지만 Safari 경로로 통일.
- package-lock.json 버전(0.7.0)이 package.json(0.8.0)과 어긋나 있음 — 다음
  `npm version patch`가 양쪽을 함께 올리며 자연 해소 예정.
