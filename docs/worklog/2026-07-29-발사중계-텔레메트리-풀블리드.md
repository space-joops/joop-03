# 2026-07-29 — SpaceX식 발사 중계 + 아케이드 텔레메트리·풀블리드 (v0.15.0)

## 배경

목표 선언이 있었다: **"우주 덕후에게 나만의 줍스를 실제 인공위성처럼 발사·운용하는
경험을 준다"**(FR-5.2 심화 + FR-5.3 착수). 레퍼런스는 SpaceX 중계 화면 — 하단
텔레메트리 바(SPEED|ALTITUDE 원형 게이지 + T+ 시계 + 이벤트 타임라인 점)와
CRS-33 실제 비행 타임라인(Max-Q T+1:12 / MECO 2:27 / 단 분리 2:30 / 부스터 착륙
~8:30 / SECO ~8:50)이다. 사용자 결정: 발사 배속 1×/4×/16×, 리플레이 localStorage,
아케이드 진입 첫 화면 직행 버튼.

## 무엇을, 왜, 어떻게

### 발사 — 12초짜리 애니메이션에서 2.5분 중계로

- **`lib/vehicle-profiles.ts`(신규)**: DB `joop_03_launch_vehicles`에 특성 컬럼이
  0개이고 관리자가 임의 이름을 넣을 수 있어, 이름 정확 매칭(시드 5종) → provider
  휴리스틱 → 기본 폴백의 3단 클라 매핑으로 프로필(단수·부스터 회수·색·1단 비율)을
  해석한다. `buildLaunchTimeline`이 CRS-33 비율로 이벤트 시각표를 만들고 —
  **boosterLanding=false 프로필은 착륙 이벤트가 아예 빠져 타임라인 점 수 자체가
  발사체마다 다르다**(Falcon 9는 9개, Electron은 8개 — 검증 스크린샷으로 확인).
  `sampleTelemetry`는 이벤트 앵커 smoothstep 보간의 연출용 속도/고도 곡선(물리 시뮬
  아님 — MECO/SECO에서 증가가 꺾인다).
- **launch-sequence.tsx 재설계**: 장면이 발사대 → 상승(Max-Q 진동) → MECO 화염 컷 →
  단 분리(1단 낙하) → 2단 점화(청백 화염) → **부스터 착륙 8초 컷어웨이**(하강·착륙
  연소·드론십, 해당 프로필만) → SECO 관성 + 지구 림 → 줍스 사출 → 궤도 호로 진행.
- **배속의 함정 두 개**: ① 배속 state를 effect deps에 넣으면 rAF 루프가 재시작돼
  진행이 리셋된다 — 버튼은 state(UI)와 ref(루프)를 동시 갱신하고 루프는 ref만 읽는다.
  가상 경과시간 `vElapsed += dt × speed` 누적. ② 16×에서는 한 프레임에 이벤트를
  2개 지날 수 있다 — 단계 전진을 if가 아니라 **while**로.
- **completeLaunch 조기 호출**: 사출(deploy) 이벤트 통과 시점에 fire-and-forget으로
  미리 호출(서버가 orbit 재진입을 ok 처리하므로 멱등·안전), 끝나면 결과만 기다려
  라우팅 — 2.5분 중계 끝의 꼬리 지연을 없앴다.
- 백그라운드 탭은 **일시정지**(visibilitychange, 복귀 시 lastTs 재설정) — 중계
  연출이므로 따라잡기보다 자연스럽다. 2분+ 시퀀스라 ResizeObserver로 회전 대응.
- config `launch_sequence_seconds`(30~300, 기본 150) 1개만 추가 — 단계 비율까지
  config로 빼는 건 과함(발사체 프로필 코드가 단일 진실).

### 텔레메트리 바 — 화면별 이원화

같은 시각 스펙(96px 바 + 원형 게이지 + T+ 대형 시계)을 쓰되 구현은 다르다:
- **발사 = DOM**(`components/telemetry-bar.tsx`): 값이 React 세계 + 배속 버튼 클릭
  요소. rAF→setState는 표시값이 바뀔 때만(속도 10단위/초 단위) — 초당 ~10회 리렌더.
- **아케이드 = 캔버스 인그림**: 값(fuel/collected/elapsed/속도)이 전부 rAF 클로저
  지역 변수라, 흩어져 있던 HUD(중앙 카운터·우측 다이얼·속도 바)를 하단 바 드로잉으로
  통째 이식하면 상태 리프팅이 0이다. 상단 헤더는 삭제하고 ← 지도/종료 버튼을 바
  바로 위 좌우로 옮겼다. 실궤도 고도(`state.altitudeKm`)를 `ALT nnn KM`로 병기.

### 아케이드 풀블리드

- 페이지 main `max-w-md`·헤더 제거 → `game-fullbleed` 클래스, 게임 컨테이너의
  `mx-3 rounded-md border` 제거(boxRef·game-surface는 유지 — 크기 측정과 iOS 제스처
  차단의 핵심). **바 존 터치는 조이스틱을 만들지 않는다**(pointerdown에서 y 필터).
- safe-area 하단은 `env()`를 JS로 직접 못 읽어 **프로브 엘리먼트로 1회 실측**.
- 하단 고정 요소 충돌: `body:has(main.game-fullbleed)`로 버전 배지·PWA 배너를 게임
  중에만 숨김. 480px+ border-inline도 풀블리드 예외.

### 천체·방향 힌트·은하

- 달을 배열에서 지구 **앞 순서**(= 뒤에 깔림)로 옮기고 parallax 0.4→0.26(지구 0.35보다
  원경), size 0.55→0.42, 태양 1.1→0.85. **`find("bg-sun")!` 크래시 지뢰 제거** —
  `SUN_POS` 상수를 export해 sunTintAlpha가 배열 재구성과 무관해졌다.
- 화면 밖 지구/달/태양은 **에지 방향 힌트**(색 원 + 셰브론 + E/M/S 글리프) — 천체
  루프의 컬링 분기에서 수집해 HUD 단계에서 그린다(중심→천체 레이를 게임 뷰 사각형에
  클램프, 바 존 제외).
- **유명 은하 5종**(안드로메다·솜브레로·소용돌이 M51·바람개비 M101·대마젤란) 마스터
  SVG → `gen:game` 파이프라인에 5행 추가(합계 ~416KB), CELESTIALS 최후방(parallax
  0.13~0.18)에 사방 분산 배치. **추가 = 마스터 1개 + TARGETS 1행 + CELESTIALS 1행.**

### 리플레이(FR-5.3 착수) + 진입 단축

- `returnToEarth`가 confirmed booking을 삭제하므로 발사체 정보는 DB에서 소급 복원
  불가 — **localStorage**(`joop03.lastLaunch.v1`)에 발사 성공 시점 기록.
  `launch/page.tsx`는 queued 전용 가드라 쿼리 방식 대신 **전용 라우트**
  `/joop/launch/replay`(서버 조회 0, 클라가 기록 읽어 `mode="replay"` 재생 — 서버
  액션·기록 저장 생략, 미사용이던 done 페이즈를 종료 오버레이로 활용).
- 진입 단축: 첫 화면(orbit일 때 primary 직행)·대시보드에 아케이드 직행 버튼 —
  3탭 → 1탭. 아케이드 서버 가드가 전 상태를 재검증하므로 안전.

## 함정 기록

- 신규 라우트의 `PageProps<"...">`는 빌드 후에야 타입이 생긴다 — 직접 타이핑으로 우회.
- dict 인덱싱 캐스트(`as Record<string,string>`)는 중첩 객체(errors) 때문에 TS가
  거부한다 — 이벤트 id→라벨은 switch 매핑 함수(`launchEventLabel`)로.
