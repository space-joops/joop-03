# 2026-07-27 · M5 디자인 납품 (아케이드 모드 + 천체 배경·위성)

## 무엇을 했나

마일스톤 단위 납품 5탄 — [로드맵](../product/roadmap.md) M5(E7 아케이드):

1. **배경 천체 4종** — 지구·달·태양(각 1024²)·은하수(2048×1024 수평 타일), 전부 WebP 총 192KB. `public/game/bg-*.webp`.
2. **위성 스프라이트** — `public/game/satellite.png`(512×256). 원근은 코드 스케일 0.15~2.4 명세.
3. **분사가스 파티클** — 코드 명세(원 감쇠 수열)로 납품(조이스틱·화염과 같은 원칙).
4. **아케이드 시안 2프레임** — [mockups/arcade.html](../design/mockups/arcade.html): 플레이 중(실제 배경 에셋 로드) + 게임오버·수거 결과.
5. **[M5 핸드오프](../design/handoff-m5.md)** — 패럴럭스 4레이어, 구역 전환(FR-7.2), HUD, 게임오버 플로우, i18n 키.

## 결정한 것들 (문제 → 선택지 → 이유)

### 1. 천체를 NASA 사진이 아니라 절차 생성으로
- **문제**: 브리프는 "NASA 공개 이미지 계열 + 라이선스 확인"을 언급. 그러나 사진은 (a) 출처·라이선스 표기를 에셋마다 관리해야 하고 (b) WebP로도 장당 수백 KB이며 (c) 벡터 게임 아트(캐릭터·쓰레기) 옆에 두면 스타일이 충돌한다.
- **선택지**: (a) NASA 사진 가공 (b) 절차 생성 벡터.
- **결정**: (b). sharp 파이프라인의 결정적 의사난수로 구름·크레이터·별·성운을 생성 — 재실행해도 동일 결과, 마스터 SVG 커밋으로 편집 가능, 총 192KB(예산 500KB/장의 1/10). NASA는 무드 레퍼런스로만. **웅장함은 사진이 아니라 스케일로**: 천체가 화면의 30~60%를 차지하게 배치 규칙을 정했다.
- 시행착오: 첫 버전 지구는 긴 구름 줄무늬 때문에 가스행성처럼 보였다 → 뭉게구름 패치(클러스터)로 교정. 은하수 성운도 플랫 타원의 딱딱한 경계 → radialGradient 페이드로 교정.

### 2. 은하수는 수평 타일
- FR-7.2(경계를 넘으면 배경이 움직임)를 위해 배경이 무한 스크롤되어야 한다. 별·성운을 좌우 가장자리 40px 안쪽에만 배치해 이음새 없이 x 반복. 세로는 화면 높이에 cover.

### 3. 위성 = 배경 오브젝트, 원근은 코드
- 위성 프레임을 여러 장 만드는 대신 1장 + **스케일 연속 보간(0.15~2.4) + z-순서 전환** 명세로. "다가옴/멀어짐"은 본질적으로 연속 변화라 프레임이 아니라 파라미터의 문제다. M5에서는 충돌 없는 배경 오브젝트로 못박아 게임 밸런스 리스크를 차단(FR-7.7 사실적 강화는 후속).

### 4. 시안이 실제 에셋을 로드
- 아케이드 시안은 `bg-galaxy.webp`·`bg-earth.webp`를 상대경로로 직접 로드한다 — 시안 승인 = 에셋 조합 승인이 되도록. 결과 화면의 수거 요약은 쓰레기 지오메트리를 아이콘으로 재사용해 "게임에서 본 것 = 결과에서 보는 것" 일관성을 유지.
