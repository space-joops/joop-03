# 홈 화면 CRT 그린+앰버 투톤 리디자인 (이슈 #5)

## 문제 상황

이슈 #5에 Gemini로 생성한 디자인 컨셉 이미지가 올라왔다: (1) 네온 그린 JOOPS 로고 + 바구니
로봇 심볼, (2) 러기드 하드웨어 베젤 안의 CRT 단말기 홈 화면 목업. 기존 구현도
카세트퓨처리즘이라 방향은 같았지만, 목업과 비교하면 뚜렷한 차이가 있었다.

- 기존 화면은 사실상 **그린 단색**이었다. `--color-secondary`(앰버)가 토큰에는 있는데
  거의 쓰이지 않았다. 목업은 **섹션 제목·수치·진행바·포인트 = 앰버 / 본문·지구·이름 = 그린**
  이라는 명확한 투톤 위계를 갖고 있다.
- 배경 토큰이 **네이비 틴트**(#05070f/#0f1826)인데 목업은 **그린 틴트 블랙**(CRT phosphor).
- 목업의 시각 언어 — 코너 브래킷 `[ ]` 섹션 프레임, 워드마크 좌우 스피드라인(≡),
  상단 앰버 상태바(G.S.T. 시계), 진행바 인바 라벨 + ▲ 틱 마커, 카드 배경 없는 터미널
  랭킹 테이블, 전면 스캔라인 — 이 구현에 없었다.

참고: 이 세션(Claude Code 원격 환경)에서는 GitHub 이슈 첨부파일(user-attachments)에
접근할 수 없어서(비공개 저장소 + 프록시 정책) 이미지를 채팅으로 직접 전달받아 확인했다.
**이슈에 이미지만 있으면 원격 세션이 못 읽으니, 앞으로 디자인 시안은 저장소에 커밋하는 것을
권장** (예: `docs/design/reference/`).

## 선택지와 결정

### 1) 토큰을 어디까지 바꾸나

- A. 목업에 맞춰 팔레트 전면 교체
- B. **변수 이름은 고정(M1 컴포넌트 참조), 네이비 틴트인 값만 그린 틴트로 교체** ← 채택

design-tokens.md가 "이름 고정, 값만 확정" 원칙을 이미 명시하고 있고, 형광 그린/앰버 등
핵심 색은 목업과 이미 일치했다. 실제로 바꾼 값은 4개뿐:
`--color-bg` #05070f→#030a05, `--color-surface` #0f1826→#0a1c10,
`--color-neutral-800` →#0d1a12, `--color-neutral-900` →#06110a.
바꾸기 전에 WCAG 대비를 스크립트로 실측했다 (fg 17.3:1, muted 7.0:1, 앰버 11.1:1,
danger 6.7:1 — 전부 AA ≥4.5:1 통과).

같은 커밋에서 배경색을 참조하는 하드코딩을 전부 동기화했다: themeColor 2곳
(`app/[lang]/layout.tsx`, `app/admin/layout.tsx`), `app/manifest.ts`, Canvas 폴백 hex
(orbital-canvas의 기존 불일치 #1f6f4a→#1e5a46도 이번에 수정), launch-sequence의 순수
하드코딩 배경 → `var(--color-bg)`. design-tokens.md에 **"폴백 hex는 토큰과 동일 값 유지,
themeColor/manifest는 --color-bg와 동기화"** 원칙을 명문화했다.

### 2) 목업의 시각 언어를 어떻게 재사용 가능하게 만드나

컴포넌트마다 스타일을 박지 않고 `globals.css`에 유틸 4개를 정의했다 (후속으로 다른
화면에도 같은 언어를 적용할 수 있게):

- `.crt-brackets` — pseudo-element 하나 + 8방향 `linear-gradient` 배경으로 네 모서리만
  그리는 브래킷 프레임. 색은 `--bracket-color`로 사용처에서 오버라이드.
- `.crt-scanlines` — `position:fixed` 오버레이(`repeating-linear-gradient` 3px 주기).
  게임 트리 body에만 적용(admin 제외). **정적 패턴이라 reduced-motion과 무관**하고, 농도는
  `--scanline-alpha`(0.14) 토큰으로 조정 — 대비를 깎는 게 확인되면 0.10까지 낮춘다.
  z-40으로 VersionBadge(z-50) 아래.
- `.panel-amber` — `color-mix` 45% 감쇠 앰버 보더. 앰버가 화면을 지배하지 않도록
  보더는 감쇠하고 텍스트만 원색을 쓰는 게 목업 균형에 맞았다.
- `.speedlines` — currentColor 가로줄 그라디언트. 워드마크 좌우 ≡ 날개.

### 3) 홈 화면 컴포넌트

- **상태바**: 목업 정체성의 핵심이라 포함하기로 결정. 순수 장식이므로 `aria-hidden` +
  i18n 미적용. 시계는 마운트 전 `--:--:--` 플레이스홀더를 렌더해 hydration 불일치를
  회피(신규 `components/status-bar.tsx`).
- **CleanupGauge**: 24세그먼트 그린 바 → 앰버 연속 진행바. 헤더 `수거한 우주 쓰레기
  [ 68.4% ]`, 채움 위 인바 라벨(전경 `--color-bg`, 11.1:1), 채움이 40% 미만이면 라벨이
  넘치므로 바 밖으로 빼는 분기. 틱 마커는 목업의 임의 수치(24/49/68%) 대신 게임적으로
  의미 있는 **25/50/75% 마일스톤**으로. 수치 텍스트는 시각 요소와 별개로 유지(접근성).
- **RankingList**: surface 카드 → 카드 배경 없는 터미널 테이블. 앰버 헤더 행 + 앰버
  구분선, `1. 이름`(fg) / `1,245,300 PTS`(앰버) / ▲▼(success/danger 유지). 줍스 색 도트는
  내 줍스 식별 요소라 유지.
- **i18n**: `firstScreen.orbitLabelTop`(en "LOW EARTH ORBIT // LIVE FEED" / ko
  "지구 저궤도 // 실시간"), `firstScreen.pointsUnit`("PTS") 키 추가. en/ko 동시 수정
  (Dictionary 타입이 en.json에서 추론되므로 구조 일치 필수).

### 4) 범위

홈 화면 + 글로벌 토큰/유틸까지만. joop/train/launch/map/admin 화면은 토큰 변경의
수혜(배경 그린 틴트)만 받고, 개별 리디자인은 후속 PR로.

## 검증

- Supabase 환경변수가 원격 세션에 없어 실데이터 렌더가 불가 → **목 데이터를 넣은 임시
  프리뷰 라우트**(`app/[lang]/preview-tmp/`, 커밋 안 함)를 만들어 Playwright + 사전 설치
  Chromium으로 스크린샷 검증했다. 참고: `_` 접두사 폴더는 App Router 라우팅에서 제외되므로
  임시 라우트 이름에 `__preview`를 쓰면 404가 난다.
- `/ko`·`/en` 393×852(디자인 브리프 기준 프레임) + 360×800: 투톤 위계·브래킷·진행바
  틱·랭킹 테이블이 목업과 정합, 360px에서 긴 이름 truncate 정상.
- `npm run lint` / `npm run build` 통과 (커밋 단위마다).

## 남은 것 / 후속 제안

- PWA 아이콘 마스터 SVG(`public/design-src/icons/`)는 자체 그라디언트 배경이라 이번 배경
  토큰 변경과 무관하게 뒀다. 아이콘 배경도 그린 틴트로 맞추려면 마스터 수정 후
  `npm run gen:icons` 재실행 (브랜드 에셋이라 별도 판단 필요).
- 다른 게임 화면(내 줍스/훈련/발사/지도)과 관리자 콘솔에 같은 투톤 언어 적용.
- 스캔라인 농도(`--scanline-alpha`)는 실기기에서 확인 후 필요하면 조정.
