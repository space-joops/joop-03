# 2026-07-29 — 교신 종료 랭킹 · 광고 위성 도킹 · 인벤토리 (v0.17.0)

## 무엇을 왜 했나

요구 6건:

1. 교신 종료 후 수거 반영 시 **랭킹 + 이번 판 랭킹 변화** 표시
2. 그 화면에 **홈으로 버튼**
3. **광고 위성 6종**(VReRV·digiNORI·SpaceX·OBITAL RADAR·UZURO Tech·SPACEMAP) — 각각 다른 모양, 광고 관리자 기능 전이므로 파일 하드코딩·클라이언트 사이드
4. 기존 광고와 달리 **집중도를 해치지 않게** — 스타워즈 우주선처럼 멀리서 서서히 웅장하게 다가와 화면 밖으로 지나가게
5. **도킹하면 보상 = 초대코드**
6. **인벤토리** — 수집 쓰레기 + 도킹 위성 + 초대코드 확인·공유

사용자 결정 2건: 초대코드는 **실제 DB 발급**(로컬 임시 코드가 아니라 — 공유받은 사람이 바로 가입할 수 있어야 의미가 있다) / 도킹 시 **게임을 멈추지 않고 작은 배너**만.

이 기능은 기존 요구사항 두 개를 처음 잇는다: **FR-7.7**(위성이 다가오고 멀어지는 원근 연출 — "후속"으로 미뤄져 있던 것)과 **FR-9.1**(초대코드 발급·공유)의 부분 구현이다.

## 1. 이번 판 랭킹 변화 — prev_rank 로는 안 되는 이유

랭킹 뷰(`joop_03_rankings_weekly`)의 `prev_rank` 는 **"7일 전 누적 기준" 순위**다. 방금 저장한 한 판으로는 움직이지 않는다. "이번 판으로 몇 계단 올랐다"를 보여주려면 **저장 전/후 순위를 각각 재야** 한다.

여기서 함정 하나: `getMyRanking` 은 `react.cache` 로 감싸여 있어 **같은 요청 안에서 두 번 부르면 두 번째도 첫 번째 값이 돌아온다**(before == after 로 보이는 버그). 그래서 `lib/rankings.ts` 를 비캐시 원본(`fetchRankings`/`fetchMyRanking`, 클라이언트 주입식)과 cached 래퍼로 분리하고, `submitArcadeResult` 액션 안에서는 비캐시 함수만 쓴다:

1. debris insert **전**에 `fetchMyRanking` → `rankBefore`(뷰에 없으면 null = 첫 진입)
2. 기존 insert + 낙관적 갱신(불변)
3. 성공 직후 `fetchRankings(admin, 5)` + `fetchMyRanking` → `{rankBefore, rankAfter, top, me}` 반환

랭킹 조회가 실패해도 `ranking: null` 로 돌려보낸다 — **랭킹은 연출이지 저장 성공의 조건이 아니다**. 클라는 null 이면 기존 문구로 폴백한다.

교신 종료(saved) 오버레이는 등락 라인("7위 → 4위 ▲3" / 첫 진입 / 순위 유지) + `RankingList`(compact, 내 행 강조) + 버튼 3개(**다시 수거** / **홈으로**(primary, `/`) / **우주 지도**)로 개편했다. 랭킹 목록까지 담으면 작은 폰에서 넘칠 수 있어 saved 분기만 `overflow-y-auto` + `m-auto`(짧으면 중앙, 길면 스크롤) 구조다. 다른 phase 는 `display: contents` 래퍼로 기존 레이아웃 그대로 둔다.

참고: 자동 수거 정산과 경합하면 rankBefore 가 몇 초 스테일할 수 있으나 연출용으로 허용한다.

## 2. 광고 위성 플라이바이 — 가짜 원근이 아니라 진짜 1/z

"멀리서 서서히, 웅장하게 다가온다"를 스크린 공간 보간(작게→크게 lerp)으로 만들면 성장 속도가 균일해서 웅장함이 안 나온다. 대신 **진짜 원근 투영**을 썼다(`lib/ad-satellites.ts`):

- 깊이 `z(t) = z0 − (z0 − zEnd)·t/T` (z0≈8 → zEnd≈0.5, T 26~34초) 를 선형으로 줄이면
- 크기 `scale = 0.55/z` 는 자동으로 **"느리게 → 급격히"** 하이퍼볼릭 곡선이 된다. 스타워즈 오프닝의 그 곡선이 수식에서 공짜로 나온다.
- 위치는 소실점 + 방향벡터 × `k/z` — 접근할수록 소실점에서 밀려나 화면 밖으로 **물리적으로 퇴장**한다(페이드아웃 없음).
- **카메라 결합항** `− camΔ·0.9/z`: 줍스가 위성 쪽으로 날면 1/z 배율로 가까워진다 → **도킹이 "쫓아가는 플레이"가 된다.**

집중도 요구(요구 4)는 드로잉 순서로 지켰다: 광고 위성은 **배경 직후·게임플레이(아이템·줍스·조이스틱) 이전** 한 곳에서만 그린다. 아무리 커져도 게임 요소를 가리지 않는다 — 근접 시에도 "뒤에 깔린 초대형 구조물"로 읽혀 오히려 착시가 강해진다. 워드마크는 화면폭 48px 이하(원거리)에서는 생략한다 — 읽을 수 없는 글자는 노이즈다.

### 에셋 — 로고는 SVG 가 아니라 캔버스가 그린다

마스터 6종(`ad-sat-*-master.svg`, **1024×512** — 근접 최대 폭 ≈1300px 라 512 마스터는 흐려진다)은 실루엣을 브랜드별로 다르게 갔다: VR 바이저+듀얼 렌즈 / 큐브 3스택+픽셀 안테나 / 플랫 패널+한쪽 세로 태양전지(스타링크풍) / 대형 파라볼라+동심 격자 / 육각+3방사 붐 / 구체+노드 궤도 링. 공통 모티프로 **하단에 광고판 패널**을 매달았다(광고 위성이니까).

브랜드 워드마크는 SVG 에 넣지 않고 **캔버스 `fillText`(ui-monospace)** 가 광고판 위에 그린다. 이유: ① 마스터 SVG `<text>` 금지 규약(폰트 치환 사고 차단) 유지 ② 게임 내 모든 텍스트와 같은 서체 ③ 원거리 자동 생략 가능 ④ 광고 관리자 단계에서 DB 로고 이미지로 대체될 부분이라 패스 아웃라인 수작업은 투자 가치가 없다. `gen:game` 의 `SVG_COPIES` 에 6행을 추가해 마스터→런타임 복사를 파이프라인에 태웠다.

### 게임 루프 배선 — phase 를 절대 건드리지 않는다

아케이드 루프는 `useEffect` deps `[phase, cfg, color, a, altitudeKm]` 에 묶여 있어 **phase 나 새 state 를 deps 에 넣는 순간 게임이 리셋된다**(이 저장소의 반복 함정). 그래서:

- 플라이바이 상태는 전부 **루프 지역 변수**(adFlyby/adPose/nextAdAt/adCamStart/adDockedThisPass). 동시 1대, 첫 등장 16~26초, 이후 40~70초 간격, 미도킹 브랜드 우선.
- 도킹 판정(z < 2.2 + 반경 원-원)은 루프가 하고, 보상 처리는 `onAdDockRef`(기존 `endGameRef` 의 역방향 다리)로 React 에 넘긴다.
- 도킹 토스트(`adToast`)와 랭킹(`ranking`)은 **deps 밖 state** — setState 로 리렌더가 일어나도 루프는 살아 있다.
- 중복 방지 2단: 패스당 1회(`adDockedThisPass`) + 브랜드당 1코드(`recordAdDock` + 서버 멱등).

## 3. 도킹 보상 — 진짜 초대코드 (마이그레이션 0)

`claimAdDockReward(brandId)` 서버 액션이 기존 `joop_03_invite_codes` 테이블에 **실제 코드를 발급**한다. 스키마에 있었지만 어디서도 안 쓰이던 **`issuer_id` 컬럼을 처음 사용**한다 — 마이그레이션 없이 "누가 발급받았나"를 기록할 자리가 이미 있었다.

- **멱등**: `issuer_id = 나 AND code LIKE 'JOOP-<브랜드라벨>-%'` 가 있으면 그 코드를 그대로 반환(재도킹 = 재발급 아님).
- 발급은 admin 발급 액션과 같은 관행: `nextInviteCodes` 재사용, PK 충돌(23505) 1회 재시도, 라벨 일련번호 소진(NN>99) 시 `randomLabel()` 폴백.
- 클라: 도킹 → `sfx.arcDock()`(낮은 3화음 상승 차임) + 캔버스 "DOCKED" 플로터 → 서버 발급 → 성공 시 localStorage 기록(`joop03.adDocks.v1`) + 토스트. **실패하면 기록하지 않는다** — 다음 패스에 자연 재시도.
- 브랜드 라벨: VRERV·DIGINORI·SPACEX·OBRADAR·UZURO·SPACEMAP (전부 `/^[A-Z0-9]{2,10}$/`).

## 4. 인벤토리

`/{lang}/joop/inventory` — 데이터가 전부 localStorage 라 **서버 가드·조회 0**(리플레이 라우트 패턴). 대시보드 버튼 컬럼의 상태 분기 **밖**(지상/궤도 어디서든 볼 것이 있다)에 진입 버튼을 뒀다.

- **수집 쓰레기**: `lib/debris-kinds.ts` 에 `parseKindCounts`(전체 카운트 순수 파서)를 신설하고 `parseTopKinds` 가 이를 재사용하게 정리. 6종 그리드(`DebrisIcon` 재사용) + 개수 + 종류별 점수. "이 기기 기록" 안내를 명시(종류별 기록은 서버에 없다).
- **도킹 위성**: 6종 전체 카드 — 도킹된 것은 브랜드 색 보더 + 도킹 일시 + **코드 박스(`select-all`)** + 복사/공유, 미도킹은 실루엣 잠금(brightness 필터). ⚠️ 코드 박스는 `.game-surface`(user-select:none) 밖 — 길게 눌러 복사가 최후의 폴백이다.
- **공유**: 이 저장소 최초의 `navigator.share` 도입. share(취소 AbortError 는 실패 아님) → clipboard 폴백 → select-all 최후 수단. admin 의 클립보드 코드는 try/catch 가 없어 복사하지 않았다(모바일은 실패 경로가 실재한다).

localStorage 스토어 규약(`joop03.adDocks.v1`, v:1 레코드, 순수 파서, useSyncExternalStore 어댑터 + 같은 탭 즉시 반영 커스텀 이벤트)은 sound-prefs 변형을 따랐다.
