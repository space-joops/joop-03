# 2026-07-28 — 수석 디자이너 UX 리뷰 5개 화면 반영 (v0.14.0)

## 배경

수석 디자이너의 UX 리뷰(+목업 이미지)가 도착했다. 총평은 뼈아프다: **"보고서가 아닌
게임이 되어야 한다."** 데이터는 풍부한데 시각적 피드백과 몰입감이 부족하다는 것.
특히 "가장 심각"으로 지목된 것이 아케이드였다 — 쓰레기 게임인데 쓰레기가 안 보이고,
수거라는 행동이 시각적으로 전혀 표현되지 않는다.

원칙: 스마트폰 세로 1순위(여력 시 디바이스 최적화). 사용자 결정 두 가지 —
① 랭킹 "수거 종류" 데이터는 DB 무변경, **로컬 스토리지에만** 저장,
② 5개 화면을 **한 PR로** 반영.

## 무엇을, 왜, 어떻게

### ① 아케이드 — 최대 투자 ("쓰레기가 안 보인다")

지적이 사실이었다. 실측해 보니 정상 상태 화면에 파편이 **~10개**뿐(스폰 간격 1.1초 ×
가로지르는 시간). 수거 피드백도 `+N` 부동 텍스트가 전부.

- **밀도**: 스폰 간격 1.1→0.7초, 동시 상한 40→60, 시작 시 뷰 안쪽 9개 프리시드(첫
  프레임부터 쓰레기밭), 배경에 미세 금속 파편 입자 레이어(별밭 패턴 복제 — 오브젝트
  0개 추가라 비용 0).
- **수거 메커니즘 시각화**: 자석 흡인(반경 0.22, 파편이 줍스 쪽으로 빨려온다 —
  게임플레이 물리라 reduced-motion에도 유지) + **관절 있는 자석 팔**을 흡인 중 가까운
  2개에 그린다(끝은 미사용 상태였던 item-magnet.svg 회수). "수거! +N" 대형 팝업
  (스케일 팝, floaters 상한 12) + 카운터 앰버 플래시.
- **HUD**: 수거 카운터를 상단 중앙 `0000` 자릿수 고정 대형으로, 연료는 우측 원형
  다이얼(중앙 % 표시), 속도는 줍스 아래 바+수치로 이동. 속도 35% 이상이면 진행 방향
  반대로 흐르는 **스피드 라인**(시드 해시 — 프레임 Math.random 금지 관용구 유지).
- **종류 카운팅**: 수거 시 종류별 카운트를 지역 변수에 모아 종료 시 1회만
  localStorage 누적(`lib/debris-kinds.ts`).

⚠️ 스폰 간격은 DB `arcade_spawn_interval` 행이 있으면 그 값이 이긴다 — 운영 반영은
관리자 콘솔에서 조정 필요.

### ② 메인 — "오염된 지구가 와닿지 않는다"

- 지구본 단색 원 → **실사 지구 이미지**(아케이드와 같은 bg-earth.webp)를 원 안에
  클립해 깔고 와이어프레임 그리드를 위에 얹었다(알파 0.55→0.35 톤다운). 2048² 원본을
  매 프레임 그리면 비싸서 **resize 때 표시 크기로 1회 축소해 오프스크린 캐시**.
- 궤도대(반경 1.05~1.43)에 **쓰레기 입자 링 110개** — starHash 시드 고정 배열(마운트
  1회), 개별 각속도로 천천히 돈다. shadowBlur 없이 fillRect 1~2px라 저비용.
- 수거량을 드라마틱하게: 인라인 SVG **쓰레기 봉투**(내부 채움 = percent, 서버 렌더) +
  수치 text-lg → display-md(24px) + `/ 5,000,000` 목표 병기(totals에 target 추가).
- 랭킹 행에 **수거 종류 아이콘 2~3개**(debris-sheet.png CSS 크롭). 내 행은 로컬
  실데이터, 타인 행은 joopId 결정적 장식(실데이터 아님 — aria-hidden, 추후 DB 종류
  컬럼 도입 시 DebrisKindIcons 데이터 소스만 교체).
- **스파크라인 제거**: 입력이 시계열이 아니라 "순위순 나열"이라 항상 우하향하는 거짓
  신호였다(1위가 주간 수거도 1위니까). 일별 집계 뷰가 생기면 재도입.

### ③ 음영 대기 — "텍스트가 너무 많다"

규칙 3줄을 음영 모드에서 숨기고, 문장 안에 파묻혀 있던 카운트다운을 **display-lg
대형 T-mm:ss + 진행 바**로 분리. 기다림이 지루하지 않게 줍스가 재활용 수거함에
파편을 비우는 연출(JoopSprite + 인라인 SVG 수거함 + CSS debris-drop 스태거).
CTA는 브래킷 대형 버튼. xpBalance/insufficientXp 이중 표시도 한 곳으로 정리.

### ④ 프로필 — "내 줍스를 크고 상세하게"

64px 한 줄 배치 → **128px 초상**(시트 프레임 원본 크기라 업스케일 0, 내 색 브래킷
프레임) 세로 스택. 버튼은 신규 `.btn-brackets` 유틸(기존 `.crt-brackets` 합성 —
브래킷 그라디언트 재활용)로 SF 프레임화. 지구 복귀 버튼도 동일 유틸로 공용화.

### ⑤ 지도 — "두 맵이 시각적으로 충돌한다"

CSS perspective로 눕히는 안은 **기각** — 두 캔버스가 getBoundingClientRect로 자기
크기를 재서 DPR·좌표가 어긋난다. 대신 위계 분리: 지구본(이제 실사+도트 링)이 主,
2D 추적 지도는 `mini` prop(높이 축소 aspect 3/1 + 톤다운 opacity 85%)으로 보조.
LinkStatus 카운트다운을 대형으로, 세부 지표(OrbitStatus)·passInfo·hint는
**`<details>` 접이식 "운용 상태"**(기본 접힘, JS 불필요)로 흡수해 동일 무게 패널
반복을 해소. 텍스트 아이콘화는 글리프 프리픽스(▲ ➤ ◎ ⇄, ◐/●)로 — 라벨은 유지해
접근성 무손실.

### 반응형(최소)

`@media (min-width:480px)`에서 게임 트리 main에 좌우 경계선 1px — 데스크톱에서
컬럼과 빈 배경이 구분되게. 그 이상(md: 그리드 등)은 이번 범위 밖.

## 검증

- Playwright(390×780, DPR2) 하네스 5컷 + **첫 화면 오버플로 0px 게이트 통과**(봉투·
  대형 수치를 넣고도 유지 — 폴백 불필요했다).
- 아케이드 버스트 캡처로 수거 순간 실증: "수거! +3" 팝업 + 카운터 플래시 + 자석 팔.
- reduced-motion 패스 1회. `tsc`·`lint`·`build` 통과.
- 이 환경은 Supabase 차단이라 가짜 데이터 하네스 방식(커밋 전 삭제).

## 배운 것 / 함정

- **린트 `react-hooks/set-state-in-effect`**: localStorage 를 effect에서 읽어
  setState 하면 걸린다. `useSyncExternalStore`(스냅샷 = 원문 문자열 — 원시값이라
  참조 안정성 자동 충족) + 렌더에서 파생으로 풀었다. SSR 스냅샷 ""→ 결정적 장식이라
  하이드레이션도 안전.
- 자석 팔 대상을 배열 인덱스로 들면 수거 splice 때 어긋난다 — 객체 참조로. 방금
  수거된 파편에 1프레임 팔이 남는 건 "집게가 잡는 순간"으로 보여 오히려 자연스럽다.
- 캔버스 HUD를 중앙/우측/하단으로 분산 배치할 때 DOM 종료 버튼(right-2 top-9)과의
  겹침을 스크린샷으로 확인할 것.

## 남은 것
