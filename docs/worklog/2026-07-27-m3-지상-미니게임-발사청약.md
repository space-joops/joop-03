# 2026-07-27 · M3 지상 미니게임 + 발사체 청약

로드맵 **M3(지상·청약)** 를 구현한 기록입니다. M2에서 분양받은 지상(ground) 줍스를 **미니게임으로 키워 레벨을 올리고**, 자격이 되면 **실 발사체에 청약**하는 흐름을 만들었습니다.

## 무엇을 만들었나

- **내 줍스 대시보드**(`/[lang]/joop`): 레벨·XP 바·상태 + [지상 훈련] · [발사 청약] 진입. 첫 화면의 "내 줍스" 배지를 여기로 링크.
- **지상 미니게임**(`/[lang]/joop/train`): 관성(마찰0) 조작으로 우주 쓰레기를 먹는 Canvas 2D 게임. 화면을 누른 방향으로 분사, 연료 소진 시 종료 → 점수만큼 XP 획득 → 레벨 상승.
- **발사체 청약**(`/[lang]/launch`): 실 발사체 리스트(Falcon 9, Electron, Ariane 6, Long March 5, Soyuz-2)에서 청약. **자격(레벨) 충족 + 정원 내면 자동 확정**, 정원 초과 시 대기(pending).

## 핵심 결정과 이유

### 미니게임 = 아케이드 조작 엔진의 지상 버전

FR-7.1에 따르면 아케이드(M5)는 "지상에서 훈련한 것과 동일한 조작 방식"입니다. 그래서 미니게임 조작을 **아케이드 코어의 축소판**으로 만들고, 물리 로직을 순수 함수 `lib/minigame.ts`에 두어 **M5에서 재사용**하도록 했습니다.

- **관성 있음, 마찰 0**(FR-7.5): `applyThrust`가 추력을 속도에 더하고 마찰=0이라 관성이 유지됩니다. 물리 상수(추력·최대속도·연료·마찰)는 `joop_03_game_config`에 두어 향후 관리자 조정(EPIC 10) 대비.
- 5원 조이스틱·분사 미세조정은 M5로, M3은 "화면을 누른 방향으로 분사"로 간소화(사용자 합의 범위).

### 청약은 자동 선별 (관리자 UI 없이 완결)

관리자 선별 UI는 M8이라, M3은 **자동 선별**로 완결시켰습니다: 청약 시 서버(service_role)가 `필요레벨 ≤ 내레벨` && `확정수 < 정원`이면 즉시 `confirmed`(줍스 상태 `queued`로), 정원 초과면 `pending`, 자격 미달이면 버튼 비활성. 정원 카운트→확정을 **단일 Server Action**에서 처리하고 `unique(vehicle_id, owner_id)`로 중복 청약을 막아 경쟁 조건을 줄였습니다.

### XP/레벨은 서버 신뢰값

미니게임 점수는 클라 Canvas에서 나오지만, **클라는 "먹은 개수"만 보내고 서버가 XP를 계산**(치팅 상한 검증)합니다. `level = 1 + floor(xp/100)`. `joops.xp` 컬럼을 추가하고 기존 M1 시드는 default 0이라 안전합니다.

## 검증

- `npm run build` / `npm run lint` 통과. 라우트 `/joop`·`/joop/train`·`/launch` 생성.
- 마이그레이션은 공유 프로젝트라 Management API로 직접 적용(발사체 5개·xp 컬럼·물리 파라미터 확인).
- 배포 후 브라우저: 분양 → 대시보드 → 미니게임 플레이·레벨 반영 → 청약·자동 확정 확인.

## 알려진 한계 / 다음

- 미니게임 밸런스(연료·추력·쓰레기 수)는 임시값 — 플레이 감각에 맞춰 튜닝 필요(파라미터는 config).
- 발사 확정(`queued`) 이후 **카운트다운·발사 중계(M4)**, 궤도 진입 후 랭킹 반영은 후속.
- 리플레이/공유(FR-5.3), 관리자 선별 UI(M8), 아케이드 풀 물리(M5).
