# 2026-07-27 · M4 발사 시퀀스 + 우주 지도

로드맵 **M4(발사·우주 지도)** 를 구현했습니다. M3에서 청약 확정된 `queued` 줍스를 실제로 **발사해 궤도에 올리고**, 우주에서의 상태를 보여줍니다.

## 무엇을 만들었나

- **발사 시퀀스**(`/[lang]/joop/launch`): 카운트다운(T-마이너스) → **Canvas 발사 애니메이션**(줍스 색 로켓 상승·단분리·궤도 진입) → 궤도 진입.
- **우주 지도**(`/[lang]/joop/map`): 내 줍스 궤도 위치(Canvas, 실시간 이동)·속도·고도·현재 상공(위경도)·음영/수신 상태. 방문 시 **idle 자동 수거 정산**.
- **대시보드 상태별 분기**(`/[lang]/joop`): `ground`(훈련/청약) · `queued`(발사하기) · `orbit`(우주 지도).

## 핵심 결정과 이유

### 발사 완료 = orbit 전환 + 궤도 파라미터 부여 → 자동으로 첫 화면에 등장

`getOrbitalSnapshot()`은 `status='orbit'`만 조회합니다(M1). 그래서 발사 완료 Server Action(`completeLaunch`)이 줍스를 **`orbit`으로 전환하고 궤도 파라미터(반경·경사·승교점·위상·각속도)를 부여**하면, 별도 작업 없이 **첫 화면의 궤도·랭킹·총 청소량에 내 줍스가 등장**합니다. "로그인 시 내 랭킹"(FR-1.8)도 이 시점에 성립합니다. `queued`→`orbit` 조건부 업데이트로 중복 발사를 막았습니다.

### idle 자동 수거 (방치형 재미)

음영 지역 자동 수거(FR-6.1)를 **방치형(idle) 정산**으로 구현했습니다: 우주 지도 방문 시 `last_collected_at` 이후 경과 × 수거율(`idle_collect_rate`)만큼 수거해 `debris_events`+`total_collected`에 반영(랭킹 상승). 경과는 `idle_collect_cap_hours`로 상한을 둬 과도한 수거를 막고, 정산은 `service_role` 단일 경로입니다. 물리적으로 정확한 음영 계산 대신, 궤도 위치의 태양 반대편 여부로 "음영/수신" 상태만 표시(게임 재미 우선).

### Canvas는 rAF 중 setState 금지 (M3 교훈 반영)

발사 애니메이션·우주 지도 모두 진행률/좌표는 Canvas 내부에서 다루고, `setState`는 카운트다운 숫자·단계 라벨·완료 신호 등 최소한만 사용했습니다. 카운트다운도 `setInterval` 콜백 안에서만 상태를 바꿔 lint 규칙(effect 내 setState 회피)을 지켰습니다.

## 검증

- `npm run build`·`npm run lint` 통과. 라우트 `/joop/launch`·`/joop/map` 생성.
- 마이그레이션은 Management API로 적용(`last_collected_at` 컬럼·수거/발사 config).
- 배포 후 브라우저: `queued` 줍스 → 발사 시퀀스 → 궤도 진입 → 우주 지도·지표, 첫 화면 궤도/랭킹 등장, idle 수거 반영 확인.
