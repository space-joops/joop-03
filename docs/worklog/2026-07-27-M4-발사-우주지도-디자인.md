## 결정한 것들 (문제 → 선택지 → 이유)

### 1. T-계기의 색 문법: 그린(대기) → 앰버(비행)
- 카운트다운 `T-MM:SS`는 primary 그린(준비·정상), 발사 후 `T+MM:SS`는 secondary 앰버(진행 중·주의)로 상태를 색으로 구분. 관제 콘솔의 계기 색 관례를 그대로 가져와 학습 비용 없이 읽힌다. 둘 다 라틴·숫자라 display 폰트 규칙에 부합.

### 2. 지도: 대륙 데이터는 개발 소관, 디자인은 스타일만
- **문제**: FR-6.3 "2차원 지구본 지도"에 대륙 윤곽이 필요하지만, 디자이너가 손으로 그린 대륙은 부정확하고 유지보수도 안 된다.
- **결정**: 대륙은 개발측 **간략화 GeoJSON**(스트로크 1px 스타일만 명세)으로 넘기고, 디자인은 투영(equirectangular)·그리드·궤적·음영 밴드·마커의 수치를 확정했다. 시안은 그리드+궤적만으로도 화면이 성립함을 보여준다(대륙은 향상 요소).
- **음영은 45° 해치 밴드**: 색만 어둡게 하면 "고장"처럼 보인다. 해치+대시 경계는 "여기는 통신 불가 구역"이라는 지도 기호 관례라 정보로 읽힌다. 음영 안 다른 줍스는 불투명도를 낮춰(0.5) 상태를 겹쳐 전달.

### 3. 로켓 화염·연기를 에셋에서 분리
- 화염은 플리커(프레임별 길이 변화), 연기는 상승에 따라 생성·확산되는 **동적 요소**라 이미지로 고정하면 어색하다. 로켓 본체만 벡터 에셋으로, 화염(2겹 곡선+플리커 규칙)·연기(원 크기/불투명도 감쇠 수열)는 수치 명세로. 조이스틱과 같은 원칙(동적인 것은 명세).

### 4. 중계 화면의 정보 우선순위
- 스페이스X 중계 문법(대형 시계 + 고도/속도 + 단계 타임라인)을 모바일 세로에 재배치: 계기(상단) → 장면(중앙) → 텔레메트리·단계(하단 반투명 패널). "내 좌석" 타일을 셋째 자리에 넣어 **내 줍스가 타고 있다**는 개인화를 유지. 리플레이/공유(FR-5.3)는 후속이라 공유 버튼 자리만 확보.

### 5. 지도 화면이 E6의 허브
- FR-6.5(초대 공유)·FR-6.6(아케이드 진입)을 지도 화면 하단에 배치해 "궤도 상태 확인 → 교신 가능이면 조종 → 친구 초대"의 루프가 한 화면에서 돈다. 교신/음영 상태에 따라 CTA 활성·문구가 바뀌는 규칙을 칩·인디케이터와 함께 명세.
