# 2026-07-27 · 음영 XP 진입 + 우주 지도 통일 + 수신 카운트다운 + 줍스 스프라이트

M5 아케이드(#41) 직후의 요청 6가지를 한 번에 반영했습니다. 핵심은 **"음영을 기다리는 시간"을 게임적으로 다룰 수 있게 만든 것**과, 첫 화면과 우주 지도가 **같은 지구본을 같은 속도로** 쓰게 만든 것입니다.

## 문제: 음영이 31~65분이었다

아케이드는 수신 지역(음영 밖)에서만 열리는데, 실제 궤도는 한 바퀴 62~131분이고 **음영은 정확히 반주기**입니다. 즉 운이 나쁘면 한 시간을 기다려야 게임을 할 수 있었습니다. 게임으로 쓸 수 있는 길이가 아닙니다.

### 음영이 정확히 반주기인 이유 (그리고 전환 시각을 정확히 아는 방법)

태양을 +x로 두면 음영은 `x(t) < 0`입니다. `positionAt`의 x를 전개하면

```
x(t) = r·R·cos(φ(t) − ψ),   R = hypot(cos Ω, cos i·sin Ω),  ψ = atan2(−cos i·sin Ω, cos Ω)
```

위상의 **순수 사인파**입니다. 그래서 (1) 음영은 정확히 반주기이고, (2) 다음 전환 시각을 수치 탐색 없이 한 줄로 구할 수 있습니다. 8만 샘플로 검증했습니다 — `positionAt`의 x<0과 오차 0, 예고한 전환 시각의 오예측 0.

## 해결: 두 개의 손잡이 (요구 5 — 설정값으로)

| config | 기본값 | 하는 일 |
| --- | --- | --- |
| `orbit_game_speed` | **30** | 궤도 위상 진행 배속. 한 바퀴 62~131분 → **2~4분** |
| `shadow_fraction` | **0.35** | 음영 호를 좁힌다(물리값 0.5). 음영 **45~90초** |

두 값의 조합으로 최대 대기가 1.5분입니다. 관리자 콘솔에서 언제든 조정할 수 있고, `orbit_game_speed=1` + `shadow_fraction=0.5`로 두면 실제 물리로 되돌아갑니다.

**왜 ω(각속도)를 직접 올리지 않았나**: `lib/space.ts`가 속도 계기를 `ω·r·6371`로 계산하므로 ω를 30배 하면 "초속 200km"가 표시됩니다. 시간만 압축하고 고도·속도는 실물리값을 유지했습니다.

## 하나의 게임 시계로 통일 (요구 2·3)

`gameTime = 실시각 × orbit_game_speed`를 **서버와 클라가 같은 식으로** 계산합니다. 그래서 음영 판정(서버)과 화면의 줍스 위치(클라)가 어긋나지 않습니다.

- `components/orbit-viewer.tsx` 신설 — 첫 화면에 인라인돼 있던 지구본/추적 지도/배속 컨트롤을 뽑아 공용화했습니다. `layout="toggle"`(첫 화면) / `layout="stack"`(우주 지도 = 지구본 위 + 펼친 지도 아래).
- 우주 지도가 쓰던 `components/space-map.tsx`는 **삭제**했습니다. 그 파일의 장점(내 궤도 링)은 `orbital-canvas`로 이식했으니 잃은 게 없습니다.
- 배속 버튼은 이제 게임 배속 **위에 곱하는 관측 배속**(1×/2×/8×/32×, 기본 1×)입니다. 1×에서 두 화면이 정확히 같은 속도로 움직입니다.

### 곁가지로 고친 것: 클라 시계 보정

가상 시계의 앵커를 `Date.now()` → **`snapshot.serverTime`** 으로 바꿨습니다. 원래 `docs/architecture/orbit-model.md`가 요구했지만 미구현이던 부분입니다. 덕분에 (1) 클라 시계가 틀어져 있어도 서버 기준 위상을 따라가고, (2) SSR/CSR 첫 렌더가 같아져 **하이드레이션 불일치가 사라졌습니다**(게임 배속 30을 켜자 이 버그가 드러났습니다 — 배속 1이던 시절엔 오차가 반올림에 묻혀 안 보였습니다).

## 수신 카운트다운 화면 (요구 4)

`components/link-status.tsx` — 교신 배지 + **T-mm:ss** + 진행 바 + 게임 배속 안내. 서버가 준 `nextChangeAt`(실제 epoch ms) 하나로 클라가 실시간 카운트다운합니다. 클라는 궤도 계산을 다시 하지 않으니 서버 판정과 절대 어긋나지 않습니다.

추적 지도의 "교신" 지표도 `shadowStateAt(설정 비율)`로 판정하게 고쳤습니다. 예전엔 물리 `x<0`이라 설정 비율이 0.35일 때 LinkStatus와 다른 값을 보여줬습니다. 우주 지도에서는 아예 추적 지도의 지표 패널을 끄고(`showIndicators={false}`) OrbitStatus·LinkStatus가 담당하게 해 중복도 없앴습니다.

## 음영에서도 XP로 진입 (요구 1)

`payShadowEntry()` 서버 액션:

- **음영 여부를 서버에서 다시 판정**합니다. 클라가 "지금 수신 중"이라고 주장해도 무료로 통과되지 않습니다.
- XP 감산은 `.eq("xp", 현재값)` 조건부 갱신 + **갱신 행 수 확인** + 재시도입니다(PostgREST에서 조건 불일치는 오류가 아니라 0행이라, 확인하지 않으면 이중 차감을 놓칩니다 — 이슈 #31에서 배운 것).
- `level`은 xp의 캐시 컬럼이라 함께 갱신합니다.

⚠️ **XP를 쓰면 레벨이 내려갈 수 있습니다**(레벨 = 1 + XP/100). 발사 자격과 얽히므로 비용 기본값을 20 XP(수거 1개 미만)로 낮게 잡았고, 0으로 두면 무료입니다. 아케이드 페이지는 이제 음영에서 리다이렉트하지 않고, 시작 오버레이가 "기다리기 vs 지불하기"를 보여줍니다. 한 판당 1회 결제이고, 다시 하기를 누르면 서버가 재판정해 그 사이 수신 지역으로 나왔다면 무료로 통과시킵니다.

## 내 줍스 스프라이트 (요구 6)

지구본과 펼친 지도 모두에서 내 줍스를 **애니메이션 스프라이트**(joop-sheet, move 2프레임 8fps) + 조준링 + 궤도 링으로 그립니다. 다른 줍스는 점이라 한눈에 구분됩니다.

> 함정: 프레임 인덱스를 게임 시각(`vt`)으로 계산했다가 배속 30배 때문에 초당 240프레임으로 깜빡였습니다. 애니메이션 진행은 **실시간**(`performance.now()`)으로 세야 합니다 — 위상은 게임 시각, 연출은 실시간.

## 검증

- `npm run build` · `npm run lint` 통과, 하이드레이션 경고 0.
- 음영 모델 단위 검증(스크립트): 8만 샘플에서 `fraction 0.5 ↔ x<0` 불일치 0, 전환 시각 오예측 0, 실제 음영 비율이 설정값과 ±0.01 내 일치.
- 하네스 + Playwright: 카운트다운 감소(T-01:10 → T-01:07), 스택 레이아웃, 스프라이트·궤도 링, 첫 화면 리팩터 정상, 음영 결제 오버레이(XP 충분 → 활성 / 부족 → 비활성 + 사유 표시), 수신 시 즉시 시작.
- 서버 액션(XP 원자 감산)은 이 환경에서 Supabase 접속이 막혀 코드 검토까지 — 프리뷰에서 실계정 확인이 필요합니다.
