# 디자인 에셋 반입: iOS 스플래시 + 줍스 캐릭터 시트 + 쓰레기 시트

## 문제 상황

디자인 스택 PR(#9→#10→#14→#17→#18→#19)에 납품된 에셋이 코드에 연결되지 않은 채
브랜치에만 쌓여 있었다. 이번에 그중 세 묶음을 반입해 적용했다:

1. **iOS 스플래시 5종** — ADR-0002가 요구하는 `appleWebApp.startupImage`가 미구현이라
   설치형(standalone) 실행 시 흰 화면이 떴다.
2. **줍스 캐릭터 스프라이트 시트** — 지상 미니게임의 줍스가 도형 렌더(코드로 그린
   로봇)였고, 캐릭터 에셋(6색 × idle/move/collect 각 2프레임)이 브랜치에만 있었다.
3. **우주 쓰레기 시트** — 미니게임 쓰레기가 별개 SVG 6종이었는데, 캐릭터와 같은
   픽셀 감성의 시트가 납품되어 있었다.

반입 방법: `git fetch origin design/m6-inventory-common-ui` 후 경로 지정
`git checkout origin/... -- <paths>` (스택 최상단 브랜치라 전체 에셋 포함).

## 선택지와 결정

### 1) 스플래시 — 그대로 연결, viewportFit 은 보류

- handoff-m1.md §3-2의 기기별 media 쿼리 5종을 `app/[lang]/layout.tsx`
  `appleWebApp.startupImage`에 그대로 연결했다. iOS는 해상도가 정확히 일치할 때만
  스플래시를 쓰므로 기기별 5종이 필수다.
- **`viewportFit: "cover"`는 이번에도 넣지 않았다** (PR #21과 같은 판단): safe-area
  env 값이 실제로 생기면서 전 화면 여백이 바뀌는데 실기기 없이 검증이 안 된다. 후속.
- 스플래시 PNG가 디자이너 v1.0 팔레트(#05080a 배경)로 그려져 있어 현 토큰(#030a05)과
  미세하게 다르다 — 둘 다 근흑색이라 근사 허용. 필요 시
  `public/design-src/brand/splash-template.svg`(디자인 브랜치)로 재렌더 가능.

### 2) 캐릭터 — 색 매핑은 hue 최근접, 게임 내는 폴백 보존

- **색 매핑**: DB 팔레트(#35e07a·#ffb23e·#38e0f0·#ff5c77·#c8ff00·#ff00d4)와 시트
  팔레트(green #39ff14 · amber #ffb000 · cyan #2de2e6 · magenta #ff2e97 · lime
  #a0ff70 · gold #ffd25e)의 hex가 다르다. `lib/joop-sprite.ts`의 `sheetForColor()`가
  **hue 원거리 최근접**으로 매핑한다 (검산: #35e07a→green, #ffb23e→amber,
  #38e0f0→cyan, #ff5c77→magenta, #c8ff00→lime, #ff00d4→magenta). **gold 시트는
  현 팔레트에서 잉여**, #ff5c77(핑크)→magenta는 근사다 — 디자이너와 팔레트 정합화가
  필요하면 후속(온보딩 setup의 COLORS 중복 정의 통합도 그때 함께).
- **DOM 노출**(브리핑·대시보드): `components/joop-sprite.tsx` — CSS `steps(2)`로
  idle 2fps 루프, reduced-motion 시 CSS `@media`로 정지(프레임 0, meta 규칙).
  JS 없는 순수 표현 컴포넌트라 서버 컴포넌트(대시보드)에서도 그대로 쓴다.
- **게임 내**: `drawJoop`을 시트 기반으로 교체하되 **기존 도형 렌더를
  `drawJoopFallback`으로 보존** — 시트 로드 실패 시 게임이 죽지 않는다(아이템 폴백과
  같은 철학). 상태 머신은 기존 값 재사용(joy→collect, 이동→move+좌이동 반전, idle),
  피격은 시트에 프레임이 없어 기존 셰이크+danger 글로우 유지. 프레임 발 위치
  anchor(93/128)를 땅에 맞춰 스케일.

### 3) 쓰레기 — 시각만 교체, 밸런스 불변

- SAFE_ITEMS를 debris-sheet 프레임 기반으로 전환 (meta 6종, sizeClass S/M/L →
  기존 크기감 기준 0.055/0.072/0.094 환산). 위성(HAZARD)은 기존 SVG 유지.
- meta의 종별 value(1~5점)는 **이번에 반영하지 않았다** — 현 점수 로직이 개당 +1이라
  게임 밸런스 변경은 별도 결정 사항. 브리핑 정답표(ItemRow)도 같은 시트를 CSS 크롭.

## 검증

- `tsc --noEmit` / `npm run lint` / `npm run build` 통과 (커밋 단위)
- 스플래시: dev 렌더에 `apple-touch-startup-image` link 5종 + media 쿼리 확인, PNG 200
- Playwright(임시 프리뷰 라우트, 커밋 안 함): 브리핑 캐릭터(green/magenta 색 매핑),
  게임 내 idle/move(이동 시 시트 move 프레임) 렌더, reduced-motion 정지, **시트 요청
  차단 시 도형 폴백 렌더** 확인, 쓰레기 시트 낙하물 확인
- 실기기 확인 필요(후속): iOS 설치 후 스플래시 표시, 실제 기기 스프라이트 성능

## 관찰 / 남은 것

- **PWA 설치 배너가 게임 화면 위에도 뜬다** (매 방문 표시 정책의 부작용) — 게임
  플레이 중에는 배너를 억제하는 개선을 후속 후보로 기록.
- 구 SVG 시안(`joop-{green,amber,cyan}.svg`, `debris-*.svg`)은 미사용 보관 —
  위성 SVG만 계속 사용 중. 정리 여부는 디자이너 확인 후.
- 시트에 피격(hurt) 프레임이 없음 — 디자이너 추가 납품 후보.
- PR #19의 배경 천체 WebP(bg-earth 등)·satellite.png·rocket.svg 는 아케이드(M5)
  몫으로 남겨둠.
