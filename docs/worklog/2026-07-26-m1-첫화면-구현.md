# 2026-07-26 · M1 첫 화면(궤도 대시보드) 구현

문서화(요구사항·아키텍처·디자인)를 마친 뒤, 로드맵의 **M1 첫 화면**을 실제 코드로 구현한 기록입니다. 이 제품에서 처음으로 "동작하는 화면"이 나온 단계라, 무엇을 어떻게 만들었고 왜 그렇게 했는지 남깁니다.

## 무엇을 만들었나

로그인 없이 보는 공개 랜딩. **줍스 100개가 지구 궤도를 실시간으로 돌고**, 누적 청소량·%·랭킹·주간 등락을 보여줍니다.

- **데이터**: 공유 Supabase(jd-04)에 `joop_03_` 4개 객체 생성 — `joop_03_joops`, `joop_03_debris_events`, `joop_03_game_config`, 뷰 `joop_03_rankings_weekly`. 줍스 100개 + 수거 이벤트 시드.
- **궤도 계산**: `lib/orbit.ts` 순수 함수(`positionAt`/`project2D`)를 서버·클라가 공유.
- **API**: `app/api/orbital/route.ts` (`revalidate = 10`) — 10초 스냅샷.
- **화면**: `app/[lang]/page.tsx`(SSR) + `components/`의 Canvas·게이지·랭킹·스파크라인·언어전환.
- **i18n**: `proxy.ts` + `app/[lang]/` + 서버 dictionaries(영/한).
- **PWA**: `app/manifest.ts`(세로 고정) + viewport.

## 핵심 설계 결정과 이유

### 1. 좌표는 "파라미터 스냅샷 + 클라 보간" (서버 부하 최소화)

이슈 요구는 "서버가 10초마다 좌표 계산, 클라는 같은 로직으로 계산"입니다. 그대로 좌표를 매초 서버가 뱉으면 부하가 큽니다. 그래서:

- 서버는 **줍스의 궤도 파라미터 + `serverTime` + 집계**만 준다(`/api/orbital`, 10초 캐시).
- 클라 Canvas가 `lib/orbit.ts`의 **같은 순수 함수**로 매 프레임(rAF) 좌표를 보간한다.

`lib/orbit.ts`를 서버와 클라가 동일 import 하므로 로직이 갈라질 수 없습니다. 순수 함수라 자체 검증(반경 보존·결정론·서버=클라 수렴)도 통과했습니다.

**위상 연속성 함정**: 처음엔 `positionAt(p, t, t0=serverTime)`로 짰는데, 스냅샷이 갱신될 때마다 `t0`가 바뀌어 줍스가 순간이동했습니다. `t0=0`(Unix epoch 기준)으로 고정해 위상을 `phase0 + ω·t`의 연속 함수로 만들어 해결했습니다. 스냅샷 갱신은 이제 파라미터·집계만 바꾸고 좌표는 끊기지 않습니다.

### 2. `revalidate = 10`이 곧 "10초 스냅샷"

커스텀 Next.js 16에서 route에 `export const revalidate = 10`을 걸면 `Date.now()` 기반 응답이 10초간 캐시(고정)됩니다. 보통은 "함정"이지만, 우리에겐 정확히 원하는 동작 — 서버가 10초마다 새 `serverTime` 스냅샷을 만드는 셈입니다.

### 3. 공유 Supabase에는 `db push` 대신 Management API로 적용

`supabase db push`가 원격 jd-04의 **다른 프로젝트 마이그레이션 히스토리**와 충돌했습니다(공유 프로젝트라 당연). 히스토리를 건드리는 `repair`는 위험하므로, 우리 `joop_03_` DDL만 **Supabase Management API(access token)로 직접 실행**했습니다. 마이그레이션 파일은 repo에 "적용된 SQL의 기록"으로 남기고, 롤백 SQL(`supabase/rollback_*.sql`)도 함께 뒀습니다. 다른 프로젝트 객체는 건드리지 않았습니다.

### 4. RLS: 공개 읽기만, 쓰기는 서버

첫 화면은 공개 데이터라 anon에 `SELECT`만 열고(정책 + GRANT), 쓰기는 `service_role`(RLS 우회)만 가능하게 했습니다. 뷰는 `security_invoker`로 호출자 권한을 따르게 했습니다. 그래서 M1은 인증이 필요 없어 anon 클라이언트(`@supabase/supabase-js`)만 씁니다 — 쿠키 세션/`@supabase/ssr`은 M2로 미뤘습니다(커스텀 Next 16의 async cookies 이슈도 회피).

### 5. i18n은 처음부터 `[lang]` 구조

나중에 도입하면 모든 라우트를 옮겨야 해서, ADR대로 지금부터 `proxy.ts`(구 middleware) + `app/[lang]/` + 서버 dictionaries로 갔습니다. 실제 번역은 영어(폴백)+한국어 2개, 나머지 언어는 목록 확정 후.

## 검증한 것

- `npm run build`·`npm run lint` 통과.
- `/` → `/en` 리다이렉트, `Accept-Language: ko` → `/ko` (proxy 로케일 감지).
- `/api/orbital` → 줍스 100개, tick 10, 집계 정상.
- `/en`·`/ko` SSR HTML에 실데이터·번역 문자열 포함.
- 궤도 순수 함수: 반경 보존(오차 4e-16)·결정론·서버=클라 수렴.

## 알려진 한계 / 다음

- **미지원 로케일 처리**: `/fr` → `/en/fr` → 404. 무한 루프는 없지만, 폴백(`/en`)으로 보내는 게 더 낫다. 개선 예정.
- **Canvas 60fps·시각 품질**은 배포 후 실제 모바일에서 확인 필요(디자이너 확정 시안 전이라 임시 카세트퓨처리즘 스타일).
- **로그인 시 내 랭킹(FR-1.8)**·초대/분양은 M2.
- PWA 아이콘은 임시 `icon.svg` — 디자이너 에셋(192/512/maskable)으로 교체 예정.
- 랭킹 등락: 100개 중 40개가 순위 변동하도록 시드. 실데이터가 쌓이면 자연스러워짐.
