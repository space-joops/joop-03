# 2026-07-27 · M2 온보딩 디자인 + 줍스 캐릭터 1차 (2순위 디자인 납품)

## 무엇을 했나

M1 납품([어제 로그](./2026-07-26-M1-디자인-산출물.md))에 이어, [브리프](../design/design-brief.md) 2순위 중 **다음 개발 마일스톤(M2 온보딩)이 실제로 필요로 하는 것**을 납품했다.

1. **줍스 캐릭터 디자인** — 색 변형 6종 × 상태 3종(대기·이동·수거) × 2프레임 스프라이트시트(`public/game/joop-sheet-*.png`, 768×128) + 좌표 메타 JSON. 인벤토리 C의 첫 항목.
2. **온보딩(둘째 화면) 3단계 완성 시안** — [mockups/onboarding.html](../design/mockups/onboarding.html): ① 초대코드 입력 → ② 분양(보급 카트리지 부팅) 연출 → ③ 이름·색 설정. ③의 색 스와치는 실제 동작(액센트 교체 레퍼런스).
3. **[M2 핸드오프 가이드](../design/handoff-m2.md)** — 플로우, 신규 컴포넌트(코드 6칸 입력·콘솔 필드·카트리지·스와치) 스펙, 스프라이트 계약·Canvas 사용 예시, i18n 키 초안.

## 왜 이 범위인가 (문제 → 선택지 → 이유)

- **문제**: 브리프 2순위는 "화면 4종 디자인"과 "게임 에셋 전체"로 넓다. 한 PR에 다 담으면 리뷰 불가능한 크기가 된다.
- **선택지**: (a) 4개 화면 시안 일괄 (b) 게임 에셋 일괄 (c) 다음 마일스톤(M2) 단위로 화면+필요 에셋을 함께.
- **결정**: (c). [로드맵](../product/roadmap.md)상 M1 다음은 M2 온보딩이고, 온보딩의 주인공이 캐릭터라 **줍스 캐릭터가 최우선 게임 에셋**이다. 화면과 에셋을 같은 PR에서 맞물리게 하면(시안 ③이 시트와 같은 지오메트리·색 세트 사용) 계약 불일치가 원천 차단된다. 미니게임(M3)·발사(M4)·우주지도(M4) 화면과 나머지 게임 에셋은 다음 납품.

## 캐릭터 디자인 결정

- **크림색 CRT 가전 셸**(#c8d2c4): 카세트퓨처리즘의 "70년대 가전 플라스틱" 미감. 다크 우주 배경에서 실루엣이 또렷하고, 형광 UI와 겹치지 않아 캐릭터가 "화면 속 UI"가 아니라 "물건"으로 읽힌다.
- **액센트 = 줍스 색**: 눈·입·안테나 팁·LED·분사염·트랙터 빔만 색이 변한다. 첫 화면 궤도 점 색(`joops[].color`) ↔ 캐릭터 색이 같은 6색 팔레트(green/amber/cyan/magenta/lime/gold)로 이어져 "궤도의 내 점 = 내 줍스" 인지가 성립한다. 색 이름↔HEX 매핑은 `joop-sheet.meta.json`이 단일 출처.
- **상태 최소 세트**: 대기(깜빡임)·이동(분사염)·수거(트랙터 빔) 각 2프레임. M3 미니게임과 M5 아케이드가 그대로 재사용 가능한 최소 어휘다. 프레임을 늘리기보다 상태를 늘리는 방향(피격·레벨업 등)을 후속으로.
- **벡터 → 시트 파이프라인**: 어제 세운 규칙(librsvg: 텍스트·필터 금지) 그대로. 지오메트리는 JS 템플릿 함수 하나에서 파라미터(색·상태·프레임)로 분기 — 색 추가는 팔레트 한 줄이면 된다. 템플릿 전문은 [핸드오프 M2 부록](../design/handoff-m2.md).

## 온보딩 화면 결정

- **분양을 "보급 카트리지 부팅"으로 연출**: 세계관(시민에게 로봇 보급)과 카세트퓨처리즘(부팅 로그, 세그먼트 진행 바, 나사 박힌 하드웨어)을 하나의 연출로 결합. 부팅 로그·진행 바는 M1 게이지 문법 재사용.
- **초대코드 6칸 세그먼트 입력**: 계기판 디스플레이 은유(display 폰트 + 블록 캐럿). 오류는 흔들림 대신 **색+문구**(reduced-motion 논쟁 회피, 접근성 단순).
- **이름·색 설정을 한 화면에**: FR-2.3의 "간단한 설정"을 유지 — 미리보기 캐릭터가 즉시 반응(스와치 → `--joop-accent` 교체)해서 설정이 놀이가 되게.

## 검증

- 시트 6종 각 16KB, meta JSON 포함 총 ~100KB. 시안 스크린샷 124KB. 전부 예산 내.
- 시안 1350px 시트 스크린샷으로 3프레임 동시 검수(코드 캐럿·부팅 바·스와치 상태 포함).
- 캐릭터 36프레임(6색×6프레임)을 그리드 렌더로 전수 시각 검수(깜빡임·분사염·빔 대비 확인, 빔 채움 불투명도 1회 조정).
