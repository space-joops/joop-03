PR #26(지상 훈련 개편)이 머지된 뒤, **첫 화면 → 온보딩 → 대시보드 → 지상 훈련 → 발사 청약 → 발사 시퀀스 → 우주 지도** 전 구간을 코드 수준에서 점검했습니다. 발견한 것 중 미니게임(제가 직전에 만든 코드)의 결함은 PR #28에서 바로 고치고, 나머지는 GitHub 이슈로 등록했습니다.

## 왜 코드 점검이었나

원래는 Vercel 프리뷰에서 실제 플레이로 점검하려 했지만, 이 작업 환경의 네트워크 정책이 `*.vercel.app` · `supabase.co`를 차단하고 있어(프록시 CONNECT 403) 배포된 사이트에 접속할 수 없었습니다. 로컬도 Supabase가 막혀 있어 인증이 필요한 페이지는 실행이 안 됩니다. 그래서 전 화면·전 액션의 코드를 읽는 방식으로 점검했고, 심각도 높음 항목은 전부 해당 파일에서 재검증한 뒤에만 이슈로 올렸습니다.

> 실브라우저 점검을 이 환경에서 하려면: Claude Code on the Web 환경 설정의 네트워크 허용 도메인에 `joop-03.vercel.app`(및 프리뷰 도메인)을 추가하면 됩니다.

## 점검하면서 배운 것 (다음 사람을 위해)

- **같은 동작의 관리자 경로와 사용자 경로를 대조하면 가드 누락이 잘 보입니다.** #29가 그렇게 나왔습니다 — 관리자 확정 액션에는 `.eq("status","ground")`와 `already_confirmed_elsewhere` 검사가 있는데, 사용자 `bookLaunch`에는 둘 다 없습니다.
- **"성공 경로가 잘 되어 있는 코드"가 오히려 누락의 증거가 됩니다.** `completeLaunch`는 `.eq("status","queued")` 조건부 업데이트로 경쟁을 막는데, 같은 패턴이 필요한 `settleIdleCollection`에는 없습니다(#31).
- **세션 생성과 자원 소진의 순서**: `redeemInvite`가 "세션 먼저, 코드 소진 나중"이라 소진 경쟁에서 진 쪽에 세션이 남습니다(#30). 부수효과가 있는 단계는 검증이 모두 끝난 뒤로 미루거나, 실패 시 되돌리는 정리 단계가 필요합니다.
- 가드가 잘 된 곳(회귀 방지용 기록): `joop/launch/page.tsx`의 3단 상태 리다이렉트, 초대 코드의 조건부 소진, 첫 화면 캔버스들의 visibilitychange + reduced-motion 처리, ko/en 사전 키 완전 일치.
