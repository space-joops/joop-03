## 배경 / 문제

이 저장소는 지금까지 AI 가 주도적으로 개발해 왔다(v0.17.0, 소스 약 1.4만 줄). 앞으로는 **사람 — 특히 파이썬 데이터 엔지니어 출신 개발자 — 이 이어받아 유지보수하고 발전**시켜야 한다. 코드 주석과 worklog 가 풍부하긴 하지만 흩어져 있고, 프론트엔드 자체가 처음인 사람에게는 "어디서부터 읽어야 하는지"의 지도가 없었다.

## 왜 이렇게 구성했나

- **모든 개념을 우리 코드 실예로만** 설명했다(가공 예제 0). 학습 자료가 곧 코드 리딩이 되도록 — 문서를 읽는 행위가 코드베이스 답사가 된다.
- 퀘스트는 **난이도·왜 중요한가·건드릴 파일·재사용할 선례·단계 힌트·검증·⚠️ 함정** 형식으로 통일했다. "작은 단위 + 성취감"이라는 요구를 형식으로 강제한 것. 첫 PR 추천(Q1·Q3·Q19)을 명시해 진입 장벽을 낮췄다.
- 퀘스트의 상당수는 **기존 이슈(#29~#37)·worklog "남은 것"의 재편집**이다 — 새로 발명하지 않고, 흩어진 부채를 "학습 커리큘럼"으로 묶었다. 이슈 번호를 남겨 추적성을 유지했다.
- 몰입감(11)과 리텐션(12)과 안정성(13)을 분리했다. 특히 안정성 문서의 프레임("몰입은 안 끊길 때 생긴다")은 버그 수정을 게임 관점 가치로 번역한 것 — 재미 문서 옆에 있어야 버그 퀘스트도 선택된다.
- 사실 검증: 문서가 인용한 코드 지점(이진 status 분기, 훈련 상한 전량 거부, redeemInvite 의 세션-먼저 순서, 에러 경계 0건, settleIdleCollection 렌더 중 호출 등)을 전부 grep/Read 로 재확인하고 썼다. 내부 링크 10건·참조 문서 9건 존재 검사 통과.

## 남은 것

- 문서는 코드가 바뀌면 낡는다 — **큰 리팩터링 PR 에는 study 문서 갱신을 체크리스트에 포함**하는 관행을 제안한다(특히 01 의 지도, 10~13 의 완료된 퀘스트 체크오프).
- 퀘스트를 실제로 수행하며 나오는 피드백("힌트가 틀렸다/부족했다")을 이 폴더에 다시 반영하는 루프가 이 문서들의 유지보수 방식이다.
