# 2026-07-26 · M1 디자인 산출물 1차 납품 (토큰 확정 · 브랜드/PWA 에셋 · 첫 화면 시안 · 핸드오프)

## 무엇을 했나

[디자인 브리프](../design/design-brief.md)의 **1순위(M1) 산출물 전체**를 만들어 repo에 반영했다.

1. **디자인 토큰 v1.0 확정** — [design-tokens.md](../design/design-tokens.md)를 초안(방향만 있던 상태)에서 실제 HEX/px 값으로 갱신. 대비(WCAG)를 전부 계산해 표로 남김.
2. **브랜드/PWA 에셋** — 심볼·워드마크(SVG), 앱 아이콘 192/512/maskable/apple-180, favicon.ico(16+32), iOS 스플래시 5종, UI 아이콘 7종.
3. **첫 화면 완성 시안** — [mockups/first-screen.html](../design/mockups/first-screen.html). 그림이 아니라 **동작하는 레퍼런스 구현**(Canvas에 줍스 100기 rAF 렌더, 게이지/스파크라인 로직 포함).
4. **개발 핸드오프 가이드** — [handoff-m1.md](../design/handoff-m1.md). globals.css 복붙 스니펫, manifest.ts/viewport 스니펫, Canvas 수치 명세, 컴포넌트 스펙, i18n 규칙.

## 왜 필요했나

디자인 발주 문서(브리프·인벤토리)는 있었지만 실제 파일이 0개라 M1 개발이 착수 불가능한 상태였다. "디자이너가 뽑아준 값과 파일"이 있어야 `app/globals.css` 토큰화, `app/manifest.ts`, 첫 화면 구현이 시작된다.

## 결정한 것들 (문제 → 선택지 → 이유)

### 1. 워드마크: 세븐세그먼트 레터폼
- **선택지**: (a) 기존 도트/픽셀 폰트로 조판 (b) 커스텀 레터폼을 직접 그리기.
- **결정**: (b). JOOPS는 다섯 글자 모두 7세그먼트로 표현 가능(J=b·c·d·e, O=전체, P=a·b·e·f·g, S=a·c·d·f·g)해서, 카세트퓨처리즘의 핵심 모티프를 로고 자체에 박을 수 있었다. 폰트 의존이 없어지고(라이선스·로딩 불필요), SVG 도형이라 어디서나 동일 렌더. 글로우 변형(`logo-wordmark-glow.svg`)에는 **소등 세그먼트 고스트**(불투명도 0.1)를 넣어 실제 계기판 잔상 느낌을 냈다.
- 인벤토리의 "단색/형광 2종"은 **2파일**로 확정: `logo-wordmark.svg`(currentColor) + `logo-wordmark-glow.svg`(자체 발광). 인벤토리에 기록.

### 2. 래스터 파이프라인: sharp(librsvg) + png-to-ico
- **문제**: 이 머신에 rsvg-convert/ImageMagick/Inkscape가 없음. PNG 아이콘·스플래시를 만들 도구 필요.
- **선택지**: (a) sharp(npm, libvips+librsvg 내장) (b) @resvg/resvg-js (c) 수동 변환 요청.
- **결정**: (a) sharp + png-to-ico. 레포 밖 임시 폴더에서만 npm install(레포에 node_modules·lockfile 오염 금지). **librsvg 함정** 때문에 마스터 SVG 저작 규칙을 세웠다:
  - `<text>` 금지 — librsvg가 시스템 폰트로 폴백해 환경마다 다르게 렌더됨. 모든 글자는 도형(path)으로.
  - 래스터 대상에 **filter(feGaussianBlur) 금지** — 글로우는 radialGradient 헤일로로. 필터는 웹 전용 SVG에만.
  - **currentColor SVG를 래스터 입력에 넣지 않기**(검정으로 나옴) — 스크립트 입력은 명시적 목록.
  - 마스터는 1024 그리드, **다운스케일만**. 파비콘은 16px에서 뭉개지지 않게 **별도 16그리드 플랫 마스터**(요소 2개: 행성 링+줍스 점).
- 재현 방법은 [핸드오프 부록 A](../design/handoff-m1.md)에. 스플래시 템플릿 전체 구현은 아래 "부록" 참조.

### 3. maskable 아이콘 안전영역
- W3C 기준 안전영역은 **중앙 원, 반지름 = 최소변의 40%**(80% 정사각형이 아님 — 모서리가 원형 마스크에 잘림). 마스터에서 핵심 콘텐츠(궤도 타원)를 r≈33% 이내로 배치하고, `clip-path: circle(40%)` 시각 검사로 확인했다. 배경은 풀블리드 불투명(#05080a).

### 4. iOS 스플래시: 정확 사이즈 5종
- iOS는 `apple-touch-startup-image`가 **기기 해상도와 정확히 일치할 때만** 적용(불일치 시 조용히 무시). Android는 매니페스트 아이콘+배경색으로 자동 생성이라 파일이 필요 없다.
- 세로 5종으로 확정: **1179×2556**(기준 프레임 393×852 @3x) · 1206×2622 · 1290×2796 · 1320×2868 · 1170×2532. 각 사이즈를 SVG 템플릿에서 **재렌더**(리사이즈 업스케일 금지). 결과물 각 86~100KB(예산 500KB 대비 여유).

### 5. display 폰트: DSEG7(선택) → Doto → VT323 → monospace
- **문제**: 세븐세그/도트 느낌 폰트는 한글·키릴을 못 담는다(10개 언어 지원 제약).
- **결정**: display 폰트는 **숫자·라틴 계기 표시 전용**으로 역할을 못박고, 본문은 system-ui+Noto 스택에 위임. 진짜 7세그 폰트 DSEG7(OFL)은 숫자·기호만 서브셋하면 woff2 10~20KB라 셀프호스트 후보로 추천(선택). Google Fonts 폴백은 Doto(도트매트릭스 가변)·VT323. 한국어 픽셀 폰트(Galmuri 등)는 풀 한글 0.5~1MB라 **M1 범위 밖 후속 옵션**으로만 기록.

### 6. 첫 화면 레이아웃: Canvas 영역을 가변 높이로
- **문제**: 시안 검수(393×852 헤드리스 스크린샷) 중 CTA가 프레임 밖으로 밀림 — 고정 높이 합계가 852를 초과.
- **결정**: Canvas 영역을 **flex 가변(최소 240px)** 으로 바꿔 남는 세로 공간을 흡수하게 함. 기준 프레임에서 ≈258px, 큰 화면에선 더 크게. 패널 밀도도 소폭 조정(랭킹 행 40→36px 등). 393/360 폭 모두 CTA까지 한 화면에 들어오는 것을 스크린샷으로 재검증.

### 7. 시안을 "동작하는 HTML"로 납품
- 정적 이미지 대신 HTML+Canvas 시안으로: (1) Canvas 수치 명세(§4)의 검증된 레퍼런스 구현이 되고 (2) 개발이 로직(게이지 세그먼트, 스파크라인 좌표, 궤도 투영)을 그대로 이식할 수 있다. reduced-motion 폴백(정지 스냅샷)도 시안에 구현되어 있다.

## 신경 쓴 정합성

- **색 단일 출처**: primary `#39ff14`는 [첫 화면 스펙](../product/screens/01-first-screen.md) API 초안의 줍스 색과 일치. 매니페스트 `theme_color`/`background_color`는 `--color-bg`(#05080a)와 동일값으로 못박음([ADR-0002](../architecture/adr/0002-pwa-portrait.md)).
- **Canvas 토큰 공유**: 시안 구현도 `getComputedStyle`로 토큰을 읽음 — 하드코딩 금지 원칙([ADR-0003](../architecture/adr/0003-rendering-canvas2d.md))의 시범.
- **앱 코드 불침범**: 디자이너 스코프로 `globals.css`·`layout.tsx`·`manifest.ts`는 건드리지 않고 **복붙 스니펫**으로 제공. 예외는 에셋 관리 규칙이 에셋 경로로 명시한 `app/favicon.ico`(교체)·`app/icon.png`·`app/apple-icon.png`(추가)뿐.
- **용량 예산**: 아이콘 PNG 7.7~28.6KB, 스플래시 86~100KB, 시안 스크린샷 88KB. 신규 바이너리 총합 ≈ 0.6MB(LFS 불필요 수준). `git check-ignore`로 무시 패턴 충돌 없음 확인.

## 배운 점

- **librsvg는 브라우저가 아니다** — 폰트·필터에서 조용히 다르게 렌더된다. "마스터는 도형만, 필터는 웹 전용" 규칙이 앞으로의 게임 스프라이트 파이프라인에도 그대로 적용된다.
- 이 머신의 헤드리스 Chrome은 최소 창 폭(500)이 있어 `--window-size=393`이 뷰포트 393을 만들지 않는다(500으로 렌더 후 축소 저장). 소형 뷰포트 검수는 **큰 창으로 찍고 프레임 영역을 크롭**하는 방식으로 우회했다.

## 부록: 스플래시 SVG 템플릿(재생성용 전체 구현)

[핸드오프 부록 A](../design/handoff-m1.md)의 `generate.mjs`에서 스플래시 부분은 아래 함수를 사용한다(엠블럼·워드마크 지오메트리는 `public/design-src/`의 마스터와 동일). 대표 결과물 1종은 `public/design-src/brand/splash-template.svg`로 커밋되어 있다.

```js
// (w, h) 각 목표 해상도로 SVG 문자열을 생성해 sharp로 렌더 — 업스케일 없음
const SPLASH_SIZES = [[1179,2556],[1206,2622],[1290,2796],[1320,2868],[1170,2532]];
function splashSvg(w, h) {
  const stars = STARS.map(([x, y, r, o]) =>            // 결정적 별 좌표 24개(0~1 비율)
    `<circle cx="${(x*w).toFixed(0)}" cy="${(y*h).toFixed(0)}" r="${r*(w/1179)}" opacity="${o}" fill="#d8e6d4"/>`).join('');
  const es = (0.72 * w) / 611;                          // 엠블럼: 궤도 가로폭 = 화면 폭 72%
  const ws = (0.5 * w) / 140;                           // 워드마크: 폭 = 화면 폭 50%
  return `<svg xmlns="http://www.w3.org/2000/svg" width="${w}" height="${h}" viewBox="0 0 ${w} ${h}">
    <defs>${DOT_GLOW_GRADIENT}${SEG_DEFS}</defs>
    <rect width="${w}" height="${h}" fill="#05080a"/>
    ${stars}
    <g transform="translate(${w/2} ${h*0.42}) scale(${es.toFixed(4)}) translate(-512 -512)">${EMBLEM}</g>
    <g transform="translate(${(w/2 - 70*ws).toFixed(1)} ${(h*0.62 - 20*ws).toFixed(1)}) scale(${ws.toFixed(4)})">${WORDMARK}</g>
  </svg>`;
}
for (const [w, h] of SPLASH_SIZES)
  await sharp(Buffer.from(splashSvg(w, h))).png({ compressionLevel: 9 })
    .toFile(join(REPO, `public/brand/splash-${w}x${h}.png`));
```
