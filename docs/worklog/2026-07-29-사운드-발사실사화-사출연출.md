# 2026-07-29 — 게임 사운드 + 발사 실사화·줌 + 사출 연출 (v0.16.0)

## 무엇을 왜 했나

사용자 요구 3건:

1. **지상 훈련·아케이드에 사운드 추가**
2. **발사 사운드 추가 + 로켓을 실제 모델에 가깝게 + 발사 장면을 줌인해 크게**
3. **사출을 더 디테일하게** — "멀리 지구가 보이고 그쪽으로 큐브형태 사출, 거기서 줍스 나옴 **삐링~**"

그동안 이 게임에는 **소리가 단 하나도 없었다**(코드 전체에 `new Audio`·`AudioContext`·mp3 참조 0건). 발사 장면의 로켓은 64×160 프레임에 화면 높이의 12.7% 크기라 "장난감"으로 읽혔고, 사출은 **5px 점 하나 + 링**이 전부였다.

## 1. 사운드 — 왜 오디오 파일이 아니라 WebAudio 합성인가

세 가지 선택지가 있었다.

| 선택지 | 장점 | 왜 안 골랐나 / 골랐나 |
|---|---|---|
| 음원 파일 반입(mp3/ogg) | 품질이 가장 좋다 | **이 환경은 네트워크 정책상 외부 음원을 가져올 수 없다.** 직접 만들 수단도 없다 |
| 라이브러리(Howler·Tone.js) | 편하다 | 의존성이 늘고, 결국 재생할 음원이 없다 |
| **WebAudio 실시간 합성** ✅ | **파일 0KB**, 의존성 0, 서비스워커 캐싱 전략 불필요, 카세트퓨처리즘 톤과 맞는다 | 채택 |

사용자에게 물어보고 **WebAudio 실시간 합성**으로 확정했다.

### 핵심 설계: 음소거를 "엔진 안"에서 강제한다

가장 중요한 결정이다. 게임 컴포넌트들은 rAF 루프를 `useEffect` 안에서 돌리는데, **deps 배열에 무언가를 추가하면 루프가 통째로 재시작된다**(이 프로젝트에서 이미 여러 번 밟은 함정이라 `speedRef` 같은 ref 관용구가 있다).

만약 게임 루프가 "음소거인가?"를 읽어야 한다면 그 상태가 deps에 들어가고, 사용자가 음소거를 누르는 순간 **게임이 리셋**된다.

그래서 뮤트 판정을 `lib/sound.ts` 안으로 밀어넣었다:

```ts
function take(): AudioContext | null {
  if (muted) return null;   // ← 여기서 끝. 오실레이터를 아예 만들지 않는다
  ...
}
```

게임 루프는 `sfx.arcCollect(n)` 을 **조건 없이** 호출한다. 결과:

- 게임 컴포넌트의 effect deps 변경 **0건** → 루프 재시작 함정 원천 차단
- "음소거 중 신규 오실레이터 0" 이라는 **계측 가능한 검증 지표**가 공짜로 생긴다

### AudioContext 는 모듈 싱글턴

발사 화면에는 자체 사용자 제스처가 없다(들어오면 바로 카운트다운이 시작된다). 브라우저 자동재생 정책상 제스처 없이는 오디오가 안 나온다. 그래서 `AudioContext` 를 모듈 싱글턴으로 두고, **직전 화면의 클릭으로 언락된 컨텍스트를 물려받게** 했다. 언락은 3중 방어:

1. `installAutoUnlock()` — 문서 최초 `pointerdown` 1회(capture)
2. START 버튼 `onClick` 첫 줄
3. 음소거 토글 아이콘 클릭 자체

⚠️ **iOS 물리 무음 스위치는 코드로 우회할 수 없다.** 토글이 켜져 있는데 소리가 없다면 기기 스위치를 확인해야 한다(토글의 `aria-label` 로는 안내가 불가능해 여기 남긴다).

### 구성

- `lib/sound.ts` — 싱글턴 컨텍스트 + 마스터 게인(0.32) + 전역 2초 화이트노이즈 버퍼 1개 공유
  - 동시 재생 상한 **8**(16× 배속에서 이벤트가 몰려도 클리핑되지 않게)
  - `gate(id, minGap)` 연타 억제, 루프 핸들 레지스트리(`stopAll()`)
  - 프리미티브 5: `blip` / `sweepNoise` / `arp` / `noiseLoop` / `toneLoop`
  - 카탈로그: 지상 8종 · 아케이드 7종 · 발사 13종
- `lib/sound-prefs.ts` — `useSyncExternalStore` + 원시 문자열 스냅샷(`debris-kinds.ts` 관용구). 같은 탭 즉시 반영용 커스텀 이벤트 1개. 키 `joop03.sound.v1`, **기본 켜짐**
- `components/sound-toggle.tsx` — 인라인 SVG 스피커(신규 에셋 0). 배치: 지상 훈련·발사·리플레이 **헤더**, 아케이드는 ready 오버레이 우상단 + 플레이 중 고스트 버튼 한 줄 위

설정이 아예 없을 때 `prefers-reduced-motion` 사용자는 **기본 꺼짐**으로 시작한다(자극 최소화). 이 판정은 반드시 **렌더 밖**(effect)에서 한다 — 렌더 중에 하면 하이드레이션이 깨진다.

### 배속별 억제 — 발사 화면

16× 로 보면 이벤트가 초당 몇 개씩 쏟아진다. 그대로 울리면 소음이다.

| 배속 | 울리는 것 |
|---|---|
| 1× | 전부 |
| 4× | 부수 이벤트(Max-Q·SECO·페어링) 제외 |
| 16× | **핵심 3개만**(리프트오프·사출·궤도 진입) |
| reduced-motion | 종료 징글 1발만 |

또 16× 에서는 **한 프레임에 이벤트를 2개 지날 수 있다**. 그래서 단계 전진 `while` 루프 안에서는 **예약만** 하고, 루프 밖에서 프레임당 1발만 울린다.

## 2. 로켓 실사화 — 실사화의 절반은 종횡비다

`rocket-master.svg` 를 다시 그렸다. 하지만 디테일보다 먼저 바꾼 건 **프레임 비율**이다.

- 기존 **64×160** (ratio 0.4) — 뭉툭한 미사일 실루엣
- 신규 **64×256** (ratio 0.25) — Falcon 9 의 가늘고 긴 실루엣

디테일: 금속 그라디언트(좌측 림 라이팅) · ogive 페어링 · **인터스테이지 검정 밴드** · **그리드핀 4장**(뒤 2장은 흐리게) · 패널 라인 · 수납 착륙다리 · **그을음 그라디언트** · 옥타웹 + 노즐 벨 3개.

> 마스터 주석의 "필터 금지(librsvg)" 규칙은 **이 파일에는 적용되지 않는다**. 그 규칙은 librsvg 로 래스터하는 에셋용이고, 로켓은 브라우저가 직접 그린다(`<text>`·외부 폰트 금지만 유지).

### ⚠️ 폭 계수 8곳 재보정

`ROCKET_RATIO` 가 0.4 → 0.25 로 바뀌면 `rh * ROCKET_RATIO` 로 만든 모든 폭이 **같이 좁아진다**. 화염·컷어웨이·착륙다리·1단 낙하·발사대 타워가 전부 여기에 걸려 있었다.

숫자로 확인해 보면:

- 구 마스터 동체 반폭 = `10/64 × 0.4rh` = **0.0625rh**
- 신 마스터 동체 반폭 = `15/64 × 0.25rh` = **0.0586rh**

동체는 절대 크기가 거의 그대로다(신 마스터가 프레임 폭을 더 꽉 채우기 때문). 즉 **화염도 절대 크기를 유지해야** 하고, 그러려면 계수에 **1.6배**를 곱해야 한다. 안 하면 화염이 로켓보다 얇아진다. 코드에 ⚠️ 주석으로 못 박아 뒀다.

### `gen:game` SVG 패스스루 — 손 복사본 문제의 영구 해결

`public/game/rocket.svg` 는 그동안 마스터의 **손 복사본**이었다. 언젠가 반드시 어긋난다. `SVG_COPIES` 5줄을 `scripts/generate-game-bg.mjs` 에 넣어 마스터 → 런타임 복사를 파이프라인에 포함시켰다(큐브샛도 같은 경로).

### 프로필별 색 — 2패스 틴트

발사체마다 본체 색이 다르다(Electron 은 검정, Ariane 은 아이보리). `source-atop` 단일 패스는 평면 채색이라 금속 그라디언트를 죽인다. 그래서 오프스크린 캔버스에서 **`multiply` → `destination-in`** 2패스로 틴트해 셰이딩을 보존한다.

## 3. 줌 카메라

이벤트 시각을 앵커로 하는 키프레임 보간(`smooth()` 재사용):

| 시점 | 배율 | 의도 |
|---|---|---|
| 리프트오프 | **2.4** | 발사대 클로즈업 |
| Max-Q | 1.6 | 상승 |
| MECO | 1.25 | |
| 2단 점화 | 1.45 | |
| SECO | **1.0** | 풀아웃 — 여기서 지구가 등장한다 |
| 사출 | 1.45 | |
| "삐링~" | **1.75** | 최대 |
| 궤도 진입 | 1.0 | 풀아웃 |

**최대가 2.6이 아니라 1.75인 이유**: 요구사항이 "멀리 지구가 보이고 **그쪽으로** 사출"이다. 즉 줍스와 지구가 **한 프레임 안에** 있어야 한다. 2.6이면 지구가 프레임 밖으로 나간다.

변환은 **앵커 고정형**(`translate(a) → scale(s) → translate(-a)`)이라 `s=1` 이면 항등 변환이다. 덕분에 SECO·종료 시점에 기존 레이아웃과 정확히 일치한다.

앵커는 사출 전엔 로켓 중심, 사출 후엔 **줍스 60% : 지구 40% 가중 중점**(구간 사이 lerp).

⚠️ 줌 안에서는 `shadowBlur/s`, `lineWidth 2/s` 로 보정한다. Max-Q 셰이크는 `/s × 1.25`. **별은 줌 밖**에 둬서 상승감을 유지한다. 부스터 착륙 컷어웨이는 **독립 카메라**(줌 미적용)다.

## 4. 사출 시퀀스 — 요구사항의 핵심

### 타임라인 재배치

`buildLaunchTimeline` 의 비율을 앞당겨 사출에 시간을 벌었다.

| 이벤트 | 기존 | 신규 |
|---|---|---|
| 부스터 착륙 | .66 | **.55** |
| SECO | .72 | **.62** |
| **페어링 분리** | — | **.66 (신규)** |
| 사출 | .90 | **.72** |

총 길이도 150초 → **180초**로 늘렸다(사용자 결정). 사출 창이 **15초 → 50초**가 됐다.

> `LaunchEventId` 에 `fairing` 을 추가하자 `telemetry-bar.tsx` 의 **exhaustive switch 가 라벨 누락을 TS 컴파일 에러로 잡아줬다**. 이 switch 는 원래 `dict.launch as Record<string,string>` 타입 우회를 피하려고 만든 건데, 안전망 역할까지 하고 있다.
>
> ⚠️ 타임라인 점이 10개가 됐다(≈286px < 366px). **이후 이벤트 추가는 금지** — 필요하면 서브페이즈로 표현할 것.

### (a) 멀리 지구

하단의 단색 ellipse "지구 림"을 버리고 **실사 `bg-earth.webp` 디스크**로 바꿨다(`orbital-canvas.tsx` 의 오프스크린 캐시 패턴 차용 — 2048² 원본을 매 프레임 축소하면 비싸다). 지름 22% → 42%, 좌하에서 떠오른다.

`ey` 계수는 SECO 직후(earthK≈0.15)에 이미 화면 하단에 림이 걸리도록 잡았다 — "SECO 풀아웃 = 지구 등장"이 카메라와 같은 박자여야 한다. 처음 잡은 값으로는 지구가 프레임 아래에 숨어서 SECO 풀아웃이 허공을 향했다.

회전은 **롤**(시선축)만 아주 느리게 준다. 자전처럼 텍스처를 흘리면 대륙이 미끄러진다.

### (b) 페어링 분리 → (c) 큐브샛 → (d) 줍스 "삐링~"

- **페어링**: ogive 반쪽 2조각이 회전하며 이탈. 본체는 `crop.top` 으로 노즈 없는 2단이 된다. 단 분리도 마찬가지로 `crop.bottom` — 기존의 "높이만 축소" 눈속임을 버리고 **실제로 잘라 그린다**.
- **큐브샛**: 2단 상부에서 지구 쪽으로 텀블링하며 이탈. 한 바퀴(2π) 돌고 −0.35rad 로 정착해 **해치가 위를 향한다**. 스프링 파티클 4개.
- **줍스**: 해치 뚜껑이 힌지로 열리고 → **`jT=0.15` 에서 "삐링~" 1회 가드** → 줍스 스프라이트가 25% 오버슛 팝(easeOutBack)으로 떠오르며 확장 링 2개.
- **궤도 진입**: 지구 중심 궤도 링(뒤 반원 α 0.25 / 앞 반원 α 0.8 로 깊이감)에 줍스가 수렴.

**"삐링~" 합성**: triangle 아르페지오 C6→F6→C7(1046.5·1396.9·2093Hz)에 square 를 겹쳐 밝기를 주고, 마지막 음에 비브라토(11Hz) 꼬리를 붙여 ≈0.6초 동안 "삐-링~"으로 들리게 했다.

부스터 착륙 컷어웨이도 이번에 실물로 바꿨다 — 민무늬 사각형 대신 마스터의 `STAGE1_FRAC~끝` 구간을 크롭해 그려서 그리드핀·그을음·옥타웹이 보인다.

## 검증 — Supabase 가 막힌 환경에서 어떻게 봤나

**핵심 레버**: `/{lang}/joop/launch/replay` 는 **서버 가드·DB 조회가 0**이다(localStorage 만 읽는다). `page.addInitScript` 로 발사 기록을 주입하면 발사 전 구간을 하네스 없이 렌더할 수 있다.

지상·아케이드는 서버 데이터가 필요해 임시 라우트(`zztrain`·`zzarcade`)를 만들어 검증하고 **커밋 전에 삭제**했다.

### 사운드 계측 — 스크린샷으로 볼 수 없는 것을 재는 법

`AudioContext` 생성자와 `OscillatorNode.start` / `AudioBufferSourceNode.start` 를 후킹해 `{주파수, 파형, 시각}` 을 수집했다.

> 함정 하나: `blip` 은 `frequency.setValueAtTime()` 으로 주파수를 **예약**하므로 `start()` 시점에 `frequency.value` 를 읽으면 기본값 440 이 나온다. `AudioParam.prototype.setValueAtTime` 도 같이 후킹해야 실제 값이 잡힌다.

| 검증 | 결과 |
|---|---|
| V1 제스처 전 AudioContext 0(자동재생 위반 없음) | ✅ ctx=0 |
| V1b 최초 포인터다운으로 자동 언락 | ✅ ctx=1 |
| V2 여러 클릭·화면 이동 후에도 컨텍스트 1개(싱글턴) | ✅ ctx=1 |
| V3 플레이 중 실제 발음 | ✅ 지상·아케이드 모두 |
| V4 50ms 버킷당 오실레이터 ≤ 8(보이스 상한) | ✅ max=3 |
| **V5 음소거 중 신규 오실레이터·버퍼 0** | ✅ 지상·아케이드 모두 증가 0 |
| V6 "삐링~" C6→F6→C7 순서 | ✅ |
| V6b 삐링~ 정확히 1회 | ✅ |
| V7 16× 이벤트음 억제 | ✅ 16×=21 < 4×=25 |
| V7b 16× 에서도 삐링~ 은 울림 | ✅ |

## ⚠️ 배포 후 확인할 것

**DB의 `launch_sequence_seconds` 가 150 으로 저장돼 있으면 관리자 콘솔에서 180 으로 바꿔야 한다.** 코드의 폴백만 180 으로 올렸다. 150 인 채로 두면 사출 창이 42초로 줄어 연출이 압축된다(동작은 정상).

`gen:game` 을 이 컨테이너에서 돌릴 때는 `GAME_BG_CHROMIUM=/opt/pw-browsers/chromium` 환경변수가 필요하다.
