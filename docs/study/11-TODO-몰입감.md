## Q7. 유대(bond)를 DB 에 영속시키기 ⭐⭐ — 첫 마이그레이션 경험으로 추천

**왜**: 지상 훈련의 유대 게이지는 `bondFrom(caught, hits)` 로 계산되지만 **결과 화면 연출로만 쓰이고 버려집니다**(FR-3.1c 의 절반만 구현). "줍스와의 관계가 쌓인다"는 반려 게임의 핵심 정서가 저장되지 않는 상태입니다.

**파일**: `supabase/migrations/`(신규 — 첫 마이그레이션!), `lib/minigame.ts`(`bondFrom` 은 이미 있음 — 재사용), `app/[lang]/joop/actions.ts` 의 `submitMinigameResult`, 대시보드/첫 화면 표시.

**힌트**:
1. 마이그레이션 작법은 기존 7개 파일이 교본입니다 — `joop_03_` 접두사, `add column if not exists`, 롤백 파일 쌍. 컬럼 하나면 됩니다: `joops.bond int not null default 0 check (bond between 0 and 100)`.
2. 저장 규칙을 정해야 합니다(설계 결정!): 매 판 덮어쓰기 vs 지수이동평균 vs 최고치 유지. "관계"라면 **천천히 오르고 천천히 식는** EMA 가 어울립니다 — `new = round(old*0.7 + game*0.3)` 정도에서 시작해 튜닝.
3. `submitMinigameResult` 액션에서 caught/hits 를 이미 받고 있는지 확인하고, 없으면 시그니처 확장. 갱신은 낙관적 동시성 관용구(04 문서 §5)로.
4. 표시: 대시보드 카드에 유대 하트/게이지. `bondTier`(cold/warm/close/best)도 lib 에 이미 있으니 문구 매핑만 하면 됩니다.
5. ⚠️ 마이그레이션은 **사람이 Supabase 콘솔에서 수동 적용**합니다(README §개발환경) — PR 본문에 SQL 적용 필요를 명시하세요.

**검증**: 마이그레이션 SQL 을 로컬에서 문법 검토 → 프리뷰에서 훈련 2판 후 bond 변화 확인.

## Q9. 아케이드에 오늘의 목표 만들기 ⭐⭐

**왜**: 아케이드의 종료 조건이 "연료 소진" 하나뿐이라, 잘해도 못해도 같은 끝입니다. **목표가 있어야 성취가 있고, 성취가 있어야 한 판 더**가 나옵니다.

**파일**: `components/arcade-game.tsx`(ready 브리핑 + saved 결과), localStorage 스토어 신규(`lib/arcade-goals.ts` 같은), dict.

**힌트**:
1. 서버 없이 시작하세요 — "오늘의 목표"를 **결정적으로** 만들면 됩니다: `starHash(연도, 일자, 0)` 으로 목표 종류(예: "패널 5개", "수거 40조각", "연료 아이템 3개")를 뽑으면 모두에게 같은 일일 목표가 DB 없이 생깁니다(05 문서 §7 의 시드 결정성 응용!).
2. 달성 판정 재료는 루프에 이미 있습니다 — `kindCounts`(종류별), `collected`, 연료 획득 카운트.
3. 달성 시 연출: `sfx` 징글 + 캔버스 플로터(기존 `pushFloater` 재사용) + saved 오버레이에 달성 배지. 보상은 일단 명예(배지)로 — 경제 연동은 12 문서의 합성 퀘스트와 함께.
4. 달성 기록은 localStorage 관용구(`joop03.dailyGoal.v1`, 날짜 키 포함)로.

**⚠️ 함정**: 목표 상태를 React state 로 루프 deps 에 넣지 말 것(그 함정 맞습니다). 루프 지역 변수 + 종료 시 1회 기록.

## Q10. `launching` 상태 살리기 — 발사의 사회화 ⭐⭐⭐

**왜**: DB 체크 제약에는 `launching` 상태가 있는데 코드가 안 씁니다(#36-4). 발사 순간 다른 사용자의 첫 화면에서는 아무 일도 일어나지 않습니다 — **"누군가 지금 발사 중"이 보이면 세계가 살아있게 느껴집니다.**

**파일**: `app/[lang]/joop/launch/actions.ts`(상태 전이), `lib/joops.ts`(스냅샷에 launching 포함), `components/orbital-canvas.tsx`(연출).

**힌트**:
1. 상태 전이 설계: 발사 시퀀스 시작 시 `queued→launching`, `completeLaunch` 에서 `launching→orbit`. 낙관적 가드(`.eq("status", ...)`) 필수. 시퀀스 이탈로 launching 에 갇히는 경우를 대비해 `completeLaunch` 가 launching·queued 둘 다 받게 하는 안전판을 고려하세요.
2. 연출: 지구본에서 launching 줍스는 지표에서 궤도로 올라가는 짧은 트레일로. `positionAt` 의 반경을 1.0→목표반경으로 시간 보간하면 됩니다(smoothstep — 05 문서 §6).
3. 스냅샷 폴링 주기(10초)가 발사 시퀀스(3분)보다 훨씬 짧아서 별도 실시간 채널 없이도 보입니다.

**⚠️ 함정**: `status: string` 이 유니온으로 안 좁혀져 있어서(#36-4) 오타가 컴파일러에 안 잡힙니다 — 이 퀘스트를 하면서 `type JoopStatus = "ground" | "queued" | "launching" | "orbit"` 으로 좁히는 것까지 하면 13 문서의 퀘스트 하나가 같이 끝납니다.

## Q11. 장식 위성에 생명 불어넣기 ⭐⭐ (FR-7.7 마무리)

**파일**: `lib/ad-satellites.ts` 의 `makeFlyby`/`flybyPose` (그대로 재사용), `components/arcade-game.tsx`.

**힌트**:
