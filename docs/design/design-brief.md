# 줍스(Joops) — 디자인 요청 브리프

> 디자이너가 가장 먼저 읽는 문서입니다. 이 프로젝트가 무엇인지, 무엇을 어떤 제약으로 만들어야 하는지, 결과물을 어떻게 전달하는지를 담습니다.
> 함께 볼 문서: [디자인 토큰 초안](./design-tokens.md) · [에셋 인벤토리](./asset-inventory.md) · [에셋 관리 규칙](./README.md)

## 1. 프로젝트 한 줄 소개

**줍스**는 지구 궤도의 우주 쓰레기를 청소하는 반려형 우주 로봇을 각자 분양받아 키우고 발사해, 다 함께 우주를 청소하는 **모바일 세로 화면 전용 웹 게임(PWA)** 입니다. → 전체 맥락: [제품 개요](../product/overview.md)

## 2. 디자인 목표 · 원칙

- **모바일 세로 전용**: 가로/데스크톱은 1차 대상 아님. 모든 화면을 **세로(portrait)** 기준으로 설계.
- **PWA(설치형)**: 홈 화면 설치, 앱처럼 몰입. 상단/하단 **safe area(노치·홈 인디케이터)** 를 반드시 고려.
- **카세트퓨처리즘(Cassette Futurism)**: 70~80년대가 상상한 미래. 아날로그 계기판, CRT 스캔라인, 세븐세그먼트/도트 디스플레이, 두꺼운 베젤, 물리 버튼·토글, 형광 그린/앰버 모노크롬 + 절제된 네온. "낡았지만 미래적인 우주 관제 콘솔".
- **다크 기본**: 우주가 배경이므로 다크 테마가 기본. 라이트는 후순위(대비 유지).
- **다국어(i18n)**: 10개 언어 + 영어 폴백. **텍스트 길이가 언어마다 크게 다르므로**(독일어·러시아어 등) 버튼/라벨은 **가변 폭**으로, 잘림 없이. CJK·키릴 가독성 고려. → [ADR-0001](../architecture/adr/0001-i18n.md)
- **접근성**: 명도 대비 확보(형광색 위 텍스트 주의), 애니메이션은 `prefers-reduced-motion` 시 정지 대안 제공, 최소 터치 타깃 44px.
- **성능**: 게임이므로 에셋 용량·프레임 예산을 지킨다(→ [에셋 관리 규칙](./README.md) 최적화 기준).

## 3. 산출물(Deliverables)과 우선순위

### 1순위 — 지금 필요 (M1 착수용)
1. **코어 디자인 시스템**: [design-tokens.md](./design-tokens.md)를 실제 값으로 확정(색 팔레트, 타이포 스케일, 간격, 핵심 컴포넌트 스타일).
2. **브랜드/PWA 아이콘 세트**: 로고(가로·심볼), 앱 아이콘(192·512·maskable), apple-touch(180), 파비콘, 스플래시.
3. **첫 화면(M1) 화면 디자인**: 아래 4-A 레이아웃 기준의 완성 시안 + 구성 요소 에셋.

### 2순위 — 이후
4. 온보딩/설정, 지상 미니게임, 발사 시퀀스, 우주 지도 화면 디자인.
5. **게임 에셋**: 줍스 캐릭터(색 변형), 우주 쓰레기 스프라이트, 배경 천체(지구/달/태양/은하수), 5원 반투명 조이스틱, 위성 등.

전체 목록은 [asset-inventory.md](./asset-inventory.md)를 기준으로 합니다.

## 4. 제약 · 핸드오프 요구사항

### 4-A. 첫 화면(M1) 레이아웃 (기준)

세로 1열. 위→아래 순서. 상세 스펙: [screens/01-first-screen.md](../product/screens/01-first-screen.md).

```
┌───────────────────────────┐
│  ▚ JOOPS        [🌐 언어]  │  상단 바: 로고 + 언어 선택
├───────────────────────────┤
│      지구본 + 궤도          │  Canvas 영역(정사각 근처)
│    · 줍스 100개 점 ·        │  움직이는 색점 + 궤도 링
├───────────────────────────┤
│  누적 청소  ▓▓▓▓▓░ 62%     │  게이지 + 수치
│  1,284,000 조각 수거        │
├───────────────────────────┤
│  랭킹        주간 등락 ▁▂▃  │  리스트 + 스파크라인
│  1. Orbita  ↑2  …          │
│  (로그인 시) 나: 37위 ↑5    │
├───────────────────────────┤
│   [ 초대코드로 시작하기 ]    │  미로그인 CTA
└───────────────────────────┘
```

### 4-B. 화면 규격

- 기준 프레임: **393 × 852**(최신 모바일 세로) 등에서 검수. **360 폭**(소형)까지 깨지지 않게, 큰 세로 화면은 콘텐츠 최대폭 + 여백.
- **safe area**: 상단 상태바/노치, 하단 홈 인디케이터 영역을 침범하지 않도록 패딩 가이드 제공.

### 4-C. Canvas 2D 핸드오프 (게임/궤도 영역)

지구본·궤도·줍스 마커·아케이드 요소는 **Canvas 2D**로 코드가 그립니다(3D 엔진 아님). → [ADR-0003](../architecture/adr/0003-rendering-canvas2d.md) 따라서:
- 벡터로 그릴 요소(지구 그리드, 궤도 링, 게이지)는 **색·선 두께·반경 비율을 토큰/수치로** 명세(단순 재현 가능해야 함).
- 비트맵 스프라이트(줍스, 쓰레기, 위성, 천체)는 **투명 PNG/WebP + 좌표 기준점(anchor)** 명시. 다중 프레임은 **스프라이트시트 + 좌표 JSON**.

### 4-D. PWA 아이콘 세트

`192`, `512`, **maskable 512**(안전 영역 준수), **apple-touch 180**, 파비콘, 스플래시. → [ADR-0002](../architecture/adr/0002-pwa-portrait.md), 배치 규칙은 [README](./README.md).

## 5. 전달 · repo 반영 방법

- 에셋은 **repo에 직접 커밋**합니다. 폴더 구조·네이밍(kebab-case)·포맷·최적화 기준은 **[에셋 관리 규칙](./README.md)** 을 따르세요.
- 반영은 **PR**로(팀은 PR 기반·한국어 소통). 시안/피드백도 PR에서 주고받습니다.

## 6. 무드보드 · 레퍼런스

- **카세트퓨처리즘**: 아날로그 우주 관제 콘솔, CRT 모니터, 세븐세그먼트 계기, 형광 그린/앰버.
- **우주 비주얼**: NASA 공개 이미지 계열(지구/달/태양/은하수). **라이선스·출처를 반드시 확인**하고, 사용 가능 소스만 반영.
- 톤: 웅장하고 경이롭되, 계기판 UI는 실용적이고 절제되게.

## 7. 리뷰 · 체크리스트

시안 제출 전 자가 점검:

- [ ] 세로 360~430 폭에서 잘림·겹침 없음, safe area 준수
- [ ] 다크 기본, 형광색 위 텍스트 대비 확보
- [ ] 다국어 최장 텍스트(독일어/러시아어 예시)로 버튼·라벨 검수
- [ ] 첫 화면의 모든 요소가 [에셋 인벤토리](./asset-inventory.md)에 항목으로 존재
- [ ] PWA 아이콘 4종(192/512/maskable/apple-touch) + 파비콘 포함
- [ ] 애니메이션에 reduced-motion 정지 대안
- [ ] 파일 네이밍·폴더·포맷이 [README 규칙](./README.md)과 일치
